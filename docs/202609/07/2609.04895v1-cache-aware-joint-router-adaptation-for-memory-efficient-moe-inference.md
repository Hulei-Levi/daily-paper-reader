## 摘要
混合专家（MoE）模型每个标记仅激活一小部分专家，但完整专家集往往超出GPU内存，导致解码期间重复的权重传输。我们将专家缓存管理形式化为模型侧算法问题，并提出一个缓存感知的后训练框架，它在保持推理时原生Top-K专家选择规则的同时，联合调整MoE主干和轻量级辅助缓存路由器。其仅更新模式（时间路由器）预测同层重用，并在不主动加载的情况下为未来标记保留专家。完整的时空路由器增加了一个空间路由器，利用因果前驱的隐藏状态在目标层访问前细化时间缓存。我们在Qwen3和GPT-OSS上跨GSM8K、MATH和CommonsenseQA数据集评估了两种模式。时间路由器在匹配的仅语言模型基线上持续提高缓存命中率并减少专家权重传输。在Qwen3上，时空路由器在三个任务中实现了最佳的负载调整效率，相对于所评估的最强预取基线，调整后命中率提高1.15至18.03个百分点，流量减少4.6%至53.3%；在GPT-OSS上的结果具有竞争力但与任务相关。仅辅助模块的消融实验保持基线准确率，但缓存增益有限，而联合后训练产生更大的改进。敏感性分析表明，缓存容量控制传输需求，而细化预算管理预访问覆盖率与主动流量之间的权衡。

## Abstract
Mixture-of-Experts (MoE) models activate only a small subset of experts per token, but the full expert set often exceeds GPU memory, causing repeated weight transfers during decoding. We formulate expert-cache management as a model-side algorithmic problem and propose a cache-aware post-training framework that jointly adapts the MoE backbone and lightweight auxiliary cache routers while preserving the native Top-K expert-selection rule at inference. Its update-only mode, Temporal Router, predicts same-layer reuse and retains experts for future tokens without proactive loading. The full Spatio-Temporal Router adds a Spatio Router that uses the causal predecessor's hidden state to refine the temporal cache before target-layer access. We evaluate both modes on Qwen3 and GPT-OSS across GSM8K, MATH, and CommonsenseQA. Temporal Router consistently improves cache hit rate and reduces expert-weight traffic over matched LM-only baselines. On Qwen3, Spatio-Temporal Router achieves the best load-adjusted efficiency across three tasks, improving adjusted hit rate by 1.15--18.03 points and reducing traffic by 4.6--53.3% relative to the strongest evaluated prefetching baseline; results on GPT-OSS are competitive but task-dependent. An auxiliary-only ablation preserves baseline accuracy but yields modest cache gains, whereas joint post-training produces larger improvements. Sensitivity analyses show that cache capacity controls transfer demand, while the refinement budget governs the trade-off between pre-access coverage and proactive traffic.

- **背景与动机**：MoE（混合专家）模型虽然每次只激活少量专家（如 Top-8/Top-4），但完整专家集远超单卡 GPU 显存，导致解码阶段需要反复从 CPU/存储搬运专家权重，形成部署瓶颈。现有缓存策略（如 LRU/LFU/LRFU）缺乏对任务相关复用模式的建模；而 ProMoE、FineMoE 等预取方法主要从系统/调度层面解决局部性问题，没有从模型侧算法上优化缓存优先级。
- **核心洞察**：本文将专家缓存管理视为**模型侧算法问题**——通过后训练阶段联合调整 MoE 主干路由行为与轻量级辅助缓存路由器，使原生路由分布更“缓存友好”，同时保留推理时原生 Top-K 专家选择规则，不改变模型推理语义。
- **意义**：将缓存直觉（时间复用、空间相邻层的预测信息）注入模型训练的损失函数中，开辟了“模型-缓存协同适配”的新思路，并能与现有离线调度/硬件加速方案正交叠加适用。

## 2. 论文提出的方法论

- **整体框架（Cache-Aware Post-Training with Auxiliary Cache Routers）**：

  - 为每个 MoE 层维护一个容量为 B 的专家缓存 C；推理阶段，未命中缓存的专家按需加载；辅助路由器只决定缓存驻留/置换，不替代原生 Top-K 选出的执行专家。
  - 两个核心组成部分：**Temporal Router（时间路由器，更新后缓存）** + **Spatio Router（空间路由器，访问前细化缓存）**，组装成两种部署模式：
    1. **Temporal Router（仅更新模式）**：只在当前层 MoE 计算完成后，决定缓存中保留哪些专家供未来 token 使用，不产生任何主动预取流量。
    2. **Spatio-Temporal Router（完整模式）**：在目标层访问之前，利用**同一 token 在上一层（或上一 token 在最末层）的因果前驱隐状态**，通过空间路由器对缓存提前做有限步替换，之后再做时间更新。
  - 辅助路由器皆为单层线性映射 + softmax，与原生路由输出加权求和得到综合缓存优先级。
- **关键技术与公式**：

  - 原生路由选择： p_{t,l}^R = softmax(W_R^l h_{t,l}) ， S_{t,l} = TopK(p_{t,l}^R)；
  - 时间缓存优先级： s_{t,l}^T = p_{t,l}^R + p_{t,l}^T （其中 p_{t,l}^T = softmax(W_T^l h_{t,l}) 预测下一 token 的同层专家需求）；
  - 空间缓存优先级： s_{t,l}^{ST} = p_{t-1,l}^R + p_{t-1,l}^T + p_{ρ(t,l)}^S ，其中 ρ(t,l) 表示因果前驱位置；空间路由器的训练目标是预测因果顺序上下一 MoE 位置的专家分布。
  - **软 Top-B 成员近似**：对专家优先级向量 s，用带温度 τ 的 sigmoid 函数 m_e(s)=σ((s_e−θ_B(s))/τ) 将硬 Top-B 离散决策变成可微形式。
  - **缓存覆盖率损失**： ℓ_cache(s,q)=Σ_e q_e(1−m_e(s))——鼓励目标专家分布（如下一 token 的原生路由分布）尽量落入辅助路由器给出的高优先集合。配合原语言建模损失共同优化： L = L_LM + λ·L_cacheλ（实验中以 s_w 表示）。
- **算法流程**（算法 1/2 的文字概括）：算法 1 为共享的后置缓存更新器：将本次激活、但缺失的专家插入缓存，若缓存已满则剔除当前未被选中且优先级最低的专家；算法 2 为完整时空路由器推理流程：先用空间优先级选出 Top-R 个候选，做有限次的主动置换（只有优先级高于当前最低者才替换），再由原生路由器选出执行专家 S，缺失专家做按需加载，最后执行算法 1 的时间更新。
- **值得注意的设计细节**：训练中不冻结原生路由参数，而让其适应缓存损失的回传；目标分布（未来/当前原生路由 softmax）只在后训练阶段作为教师信号被离线/预知使用，推理时所有输入均为可获得的因果信息。

## 3. 实验设计

- **数据集**：GSM8K（小学算术推理）、MATH（竞赛数学）、CommonsenseQA（常识问答，因无公开测试标签，仅报告验证集准确率）。

  - GPT-OSS-20B：约 21B 总参数，24 层，每 MoE 层 32 个本地专家，Top-4 激活。
- **对比基线（Baselines）**：
  - 经典缓存替换策略：LRU、LFU、LRFU（跑在匹配的仅训练语言模型损失的骨干上）；

  - 自对照模式：只在辅助路由器上训练（冻结骨干）的 auxiliary-only 消融；只使用空间预取而无时间保留的 Spatio-only。
- **指标**：
  - 任务准确率；硬缓存命中率 Hit；负载调整命中率 AdjHit = 1-(D+P)/(A+P)；每解码 token 传输的专家权重流量 Load/token = (D+P)·S_exp/T。其中 D 是按需缺失次数，P 是主动预取次数，主动预取会给命中率“扣分”，避免只看命中率虚高。

## 6. 主要结论与发现

- **Temporal Router 是有效的纯更新型方案**：相比最强经典替换策略，在 Qwen3 三任务上命中率提高约 10.5、10.7、33.3 点，流量从 1353/1294/1512 降至 974/906/304 MB/token；在 GPT-OSS 上也保持最高命中率（与最低 Load），且仅增加 2.2M 参数。
- **Spatio-Temporal Router 在预取方法中表现出最佳负载调整效率**：在 Qwen3 三任务上，调整命中率相对 ProMoE 提升 1.15–18.03 点，流量降低 4.6%–53.3%；在 GPT-OSS 上效果任务相关（第一、第二与较低存在）。
- **模式定位明确**：Temporal Router 总流量更低（零主动预取）；完整模式以可控主动流量换取更高原始命中率与提前可用性，两者服务不同工作负载约束。
- **联合微调是增益的主要来源**：仅训练辅助路由器（冻结骨干）几乎不降准确率，但缓存改进非常有限；只有联合更新原生路由分布（将缓存目标纳入主干后训练），才能大幅提升命中并显著降低按需替换流量。
- **命中率不应脱离主动流量单独评估**：TEM 可通过固定选项集达到 100% 原始命中，但调整后命中率/负载/准确率综合并不理想；增高缓存损失权重 s_w 会加剧路由集中（选择熵降低、最大频率上升），流量缓解的同时带来准确率回退（s_w=2 时 Accuracy 下降 8.9–10.8 点），提醒存在质量—缓存效率之间的权衡。
- **容量 B 为主、预算 R 为辅助**：B 增大可系统性减少传输需求；R 增大仅在预取增加的部分大于所减少的按需缺失量前有意义，R=B 会产生显著过取、调整后命中率大幅恶化。

## 7. 优点

- **切入角度清晰新颖**：把缓存管理研究对象从“系统调度”转为“路由分布学习”，在不改变推理时 Top-K 规则的前提下把缓存目标后向传播进模型本身，具备良好的部署兼容性。
- **设计统一且有模块化思想**：Temporal Router 与 Spatio Router 可堆叠、可单独使用，在同一套后训练框架下支持 update-only 与 prefetch 两种工作模式；推理协议简单、与具体硬件调度无关。
- **目标函数设计注重可微性与可解释性**：soft Top-B 近似避免离散操作，用 sigmoid 边界平滑监督；缓存覆盖率损失稀疏、稳定；用相等权重简单相加路由器分数而不是增加额外融合层。
- **指标设计有科学意识**：不以单纯命中率评价预取（否则极易被过度预取虚增），坚持 Load/token 作为主导成本，并以调整命中率做补充刻画，对结果解释比较可信。
- **实验过程做了细致的消解**：清晰利用了 backbone-only、auxiliary-only、temporal-only、spatio-only 与 joint 的对比，证明了各自组件的作用与“联合后训练 > 补丁式辅助器”的关键结论；其参数开销远小于 ProMoE。

- **公平性存在隐性风险**：经典基线（LRU/LFU/LRFU）运行在经语言建模损失后训练的同一骨干上，而 ProMoE、FineMoE 等原始实现往往使用各自的骨干/学习率/路由初始化，文中按"统一记账协议"重实现可提高口径一致性，但原始权重状态差异难以完全消除；TEM 将专家绑定为固定子集，其"命中"语义本就与开放置换空间不同，与之比较时结论需谨慎解读。
- **训练稳定性信息缺失**：λ 从 0.1 增至 2.0 时精度单调下滑，但未见训练曲线、逐 seed 方差或梯度范数分析；路由分布集中化是否在更长时间训练后自我强化/雪崩（路由坍塌的另一种形态）未做检验。
- **近似的量化误差未被讨论**：soft Top-B 通过 sigmoid 带温度逼近离散成员关系，B 越大、专家间优先级越接近时近似误差越大，文中未提供该误差与其对缓存决策影响的数值分析。

## 9. 综合评价与应用建议

整体上，这是一篇**问题定义清晰、实验设计扎实、工程落地意识强**的模型-系统协同工作。其最大贡献不在于提出某一种新的替换算法，而是重新定义了问题的归属：与其为 MoE 部署开发更聪明的调度器，不如直接让路由分布在训练后期"学会"适应缓存这一稀缺资源——这种把系统约束注入模型训练目标的视角，对后续 MoE 推理优化研究具有方法论的借鉴价值。值得借鉴的亮点包括：以 Load/token（而非命中率）作为主度量来防止预取作弊；用 Temporal-only 与 Spatio-Temporal 两种模式解耦"更新缓存"与"预取缓存"两类问题；以及通过 backbone-only/auxiliary-only 等细致的消融确认了联合微调的必要性。

在应用层面，它适合作为**已有 MoE 推理栈之上的一层后训练插件**：若部署环境带宽严重受限且不允许额外预取流量，选择 Temporal Router 即可获得大部分收益；若网络带宽充裕但延迟敏感，可启用 Spatio-Temporal Router 用较小主动流量换取提前可用性。需要注意的是，其收益的最优超参（缓存容量、细化预算、缓存损失权重）可能随模型规模、任务分布和硬件带宽变化而漂移，实际部署前应在目标数据集上重跑 λ/B/R 的小范围扫描，并辅以端到端时延测量而非仅看流量指标。对研究者而言，一个自然的后续方向是：将"缓存友好度"纳入预训练路由正则化，或将其与在线学习式调度器结合，从而降低后训练阶段对离线教师信号的依赖。
