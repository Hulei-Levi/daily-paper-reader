## 摘要
多领域微调通常将 MoE 路由与 LoRA 结合，假设 token 级路由能够分离各领域特有的更新。我们使用 Python 代码搭配生物医学文本和数学推理，在 MoE+LoRA 中检验了这一假设。尽管这些领域表现出近乎不相交的专家路由，但添加生物医学数据显著增加了代码困惑度，表明仅靠路由分离可能无法防止负迁移。为了定位失败原因，我们引入了 Jaccard 路由重叠和适配器梯度余弦相似度，分别衡量专家共享和更新兼容性。这些诊断表明，干扰主要源于在同一个低秩适配器子空间内竞争的近似正交的领域梯度。我们通过 SpawnLoRA 解决该问题，当检测到适配器级竞争时，在 MoE 专家内部动态添加门控子适配器，同时保持路由固定。我们在 Phi-tiny-MoE-instruct 和 OLMoE-1B-7B 上评估了 SpawnLoRA，在多种混合设置下，与标准和秩自适应 LoRA 相比，它有效减少了负迁移。这些结果表明，专家内部的结构性分离带来的益处超出了单纯路由或秩扩展。

## Abstract
Multi-domain fine-tuning often combines MoE routing with LoRA, assuming that token-level routing separates domain-specific updates. We test this assumption in MoE+LoRA using Python code paired with biomedical text and mathematical reasoning. Although these domains show near-disjoint expert routing, adding biomedical data substantially increases code perplexity, indicating that routing separation alone may not prevent negative transfer. To localize the failure, we introduce Jaccard routing overlap and adapter-gradient cosine similarity, which measure expert sharing and update compatibility, respectively. These diagnostics indicate that interference arises mostly from nearly orthogonal domain gradients competing within the same low-rank adapter subspace. We address this issue with SpawnLoRA, which dynamically adds gated sub-adapters inside MoE experts when adapter-level contention is detected, while keeping the router fixed. We evaluate SpawnLoRA on Phi-tiny-MoE-instruct and OLMoE-1B-7B across multiple mixture settings and find that it effectively reduces negative transfer compared with standard and rank-adaptive LoRA. These results demonstrate that structural separation inside experts provides benefits beyond routing or rank expansion alone.

## 1. 核心问题与整体含义

多领域（Multi-domain）微调常将 Mixture-of-Experts（MoE）路由与低秩适配（LoRA）结合，其隐含假设是：token 级路由可以将不同领域的 token 分配到不同专家，从而实现自然的领域隔离，避免负迁移。然而本文对这一假设提出质疑，并聚焦于一个关键问题：

> **即使 MoE 路由能够将不同领域分离到不同的专家集合上，附加在这些专家上的共享 LoRA 适配器内部是否仍会发生领域间干扰？**

为了研究该问题，文章以“Python 代码”作为受保护的锚点领域，分别搭配“生物医学文本”（严重领域失配）和“数学推理”（中等领域失配）。实验结果揭示了一个反直觉现象：尽管两个领域的专家路由几乎不相交（Jaccard 重叠度仅 ≈0.056），加入生物医学数据仍会显著升高代码困惑度。这表明**路由级分离并不足以防止适配器层面的负迁移**，其根源在于“近正交的领域梯度在同一个低秩适配器子空间内竞争”——文章称之为 **intra-adapter subspace contention**（适配器内部子空间竞争）。

整体含义是：在 MoE+LoRA 的多域微调中，不能仅依赖路由来阻止干扰；需要更精细的结构性隔离机制，而非一味扩大共享秩。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 诊断方法

为了定位负迁移产生于“路由层”还是“适配器内”，文章提出两个诊断指标：

- **Jaccard 路由重叠**  
  衡量两个领域（例如代码和生物医学）激活的专家集合之间的重合度。取值范围为 0（完全不相交）到 1（完全相同）。在 Phi-tiny-MoE-instruct 上观测到平均重叠约为 0.056，说明 **路由层几乎完全隔离了两域**。

- **Adapter 梯度余弦相似度**  
  计算两个领域各自在共享 LoRA 适配器上的梯度向量之间的余弦值。值为 +1 表示完全对齐，0 表示正交，-1 表示完全对立。实验中观测到 `cos(g_code, g_medical) ≈ −0.002 ± 0.003`，且 75% 的采样结果为负值，说明两域的更新方向在低秩子空间内**不兼容甚至轻微对立**，但并非直接冲突。

上述两个诊断组合判断：负迁移主要发生在适配器子空间内部，而**不是路由路径的共享**。

### 2.2 SpawnLoRA 方法核心思想

受诊断结果启发，SpawnLoRA 的基本思路是：不修改路由器，也不无限扩大共享秩，而是在检测到适配器级争用的专家内部**动态新增独立的门控子适配器（sub-adapter）**，为不同领域提供结构性分离路径。

- **架构公式**：每个专家 \(k\) 的输出为  
  \[
  E_k(x) = W_kx + L_{k,0}(x) + \sum_{j=1}^{J_k} \mathrm{ReLU}(w_{k,j}^\top x) \, L_{k,j}(x)
  \]
  其中 \(W_k\) 为冻结的专家权重，\(L_{k,0}\) 为始终活跃的基座 LoRA，\(L_{k,j}\) 为额外生成的子适配器，由可学习的 ReLU 门控标量 \(\mathrm{ReLU}(w_{k,j}^\top x)\) 控制其对不同 token 的动态激活。

- **Spawn 触发条件**：在滚动窗口 \(N\)（默认 15 步）内同时满足两个条件才生成新的子适配器：
  1. **当前基座适配器重要性分数停止提升**（平台期），表明现有低秩路径已饱和或趋于停滞；
  2. **两个领域的平滑损失差距持续超过阈值 δ**，表明冲突尚未消解。

- **初始化**：子适配器 \(A\) 矩阵从现有适配器未能捕获的残差梯度方向（通过 SVD 等）初始化，\(B\) 矩阵初始化为 0，以保证新增路径不立即改变模型输出。门控向量按极小方差初始化。

- **参数开销**：单子适配器开销为 \(O(r_s d)\)，只在发生争用的专家内生成，且每专家最多 \(J_\text{max}=10\) 个。保持原 MoE 路由器完全冻结，不需要领域 ID 标签。

### 2.3 与单纯秩扩展的对比

文章解释：DR-LoRA 这类秩自适应方法是在已有适配器内“扩容量”，但多域梯度仍会在同一个低秩子空间内交互；而 SpawnLoRA 通过生成独立通道来“隔离”梯度流，而不是给它们提供更多相互竞争的共享方向。

## 6. 主要结论与发现

1. **路由分离成功不等于适配器无干扰**：在几乎不相交的专家路由下，领域间仍存在显著的代码困惑度上升。
2. **干扰产生于低秩适配子空间内的“近正交梯度竞争”**：多个领域更新方向互不支持、亦不直接冲突，但共享同一低秩参数空间，导致负迁移。
3. **单纯增加共享秩无法解决问题**：DR-LoRA 在严重冲突下甚至比固定秩 LoRA 更差，说明“共享容量扩展”会让领域有更多互相干扰的方向。
4. **结构性分离优于共享式扩展**：SpawnLoRA 通过动态新增受 ReLU 门控的子适配器，在不改动路由器的前提下显著降低负迁移，且有稳定训练方差、降低种子敏感性的额外收益。
5. **跨架构普遍适用**：在 Phi-tiny-MoE-instruct 和 OLMoE-1B-7B 两种差异较大的 MoE 上均有效；多层 SpawnLoRA 还能进一步改进。

## 7. 优点

- **功能评估信号弱**：小规模下 pass@1 和下游任务（如 PubMedQA 任务准确度）不具备信息量，导致主要结论仍依赖困惑度指标，与真实任务性能的相关性存在一定不确定性。
- **架构覆盖不足**：仅测试了两种 MoE；对于含共享专家设计的架构（如 DeepSeek-V2），其争用模式和 SpawnLoRA 的适用性可能需要重新设计，文中仅给出初步展望。
- **机制本身的失效条件**：当领域样本高度不平衡时，EMA 损失差可能被大域稀释，导致触发延迟甚至不触发；当 \(J_\text{max}\) 达到上限后，继续产生的干扰无法被彻底隔离。这说明方法对超参（δ、Jmax、样本比例）仍较敏感。
- **基线公平性存疑**：DR-LoRA 在 batch size=1 下出现秩惩罚调度假象，其 Run A PPL 异常偏高，文中虽解释为 artifact，但也意味着与 DR-LoRA 的对比并不总能体现“方法本身”的真实差距。
- **代码和模型权重尚未公开**：文末仅写入“Code will be released upon acceptance”，当前结果无法完全独立复现。
