## 摘要
混合专家（MoE）语言模型常常超出单个 GPU 的内存容量。专家卸载将大多数专家保留在主机内存中并按需加载，因此解码速度取决于每个 token 必须获取多少专家。缓存和预取只能在路由允许的范围内降低这一开销。仅微调路由器可以重塑路由以复用专家，但它使专家保持冻结，因此专家无法适应新路由发送给它们的 token。我们提出 MaskCoFT，一种掩码协同自适应微调方法，仅使用交叉熵损失联合训练路由器和专家。在微调期间，可学习的二值掩码将每层的 Top-K 路由限制到专家子集，专家则适应被重定向到它们的 token。在推理时，学习到的掩码成为一种软先验，对专家重新排序，因此每个专家仍可被选择。我们为 Mixtral-8x7B 模拟每层 4 个专家的 GPU 缓存，为 DeepSeek-V2-Lite 模拟 12 个。相比基础模型，MaskCoFT 将每个 token 的专家获取次数分别减少 23.7% 和 10.1%。在实际卸载系统服务中，它将每输出 token 的时间分别最多降低 16.4% 和 5.5%。其在九个基准上的平均准确率分别比基础模型高 0.92 和 0.53 个百分点。

## Abstract
Mixture-of-experts (MoE) language models often exceed the memory of a single GPU. Expert offloading keeps most experts in host memory and loads them on demand, so decoding speed depends on how many experts each token must fetch. Caching and prefetching reduce this cost only as far as the routing allows. Router-only fine-tuning can reshape the routing to reuse experts, but it keeps the experts frozen, so they cannot adapt to the tokens the new routing sends them. We propose MaskCoFT, a masked co-adaptive fine-tuning method that trains routers and experts together with the cross-entropy loss alone. During fine-tuning, a learnable binary mask restricts the Top-K routing of each layer to a subset of experts, and the experts adapt to the tokens redirected to them. At inference, the learned mask becomes a soft prior that re-ranks experts, so every expert remains selectable. We simulate a GPU cache of 4 experts per layer for Mixtral-8x7B and 12 for DeepSeek-V2-Lite. MaskCoFT cuts expert fetches per token by 23.7% and 10.1% relative to the base model. In real offloading system serving, it lowers the time per output token by up to 16.4% and 5.5%, respectively. Its average accuracy over nine benchmarks stays above the base model by 0.92 and 0.53 points.

# MaskCoFT 论文深度总结

## 1. 核心问题与研究背景

- **MoE 的内存瓶颈**：MoE 模型通过稀疏激活降低单 token 计算量，但参数总量仍随专家数增长。路由专家占据 Mixtral-8×7B 参数的 96.6%、DeepSeek-V2-Lite 的 91.7%，权重常超出单张 GPU 显存。
- **卸载系统的解码瓶颈**：专家卸载把大部分专家留在主机内存、按需加载。解码时若命中的专家不在 GPU 缓存中，就需经 PCIe 传输。论文引用 MoE-Offloading 的剖析结果：Mixtral-8×7B 中专家加载占解码时间 86%，而专家计算仅 3%。因此解码速度本质上取决于**每 token 需要取多少专家**。
- **现有手段的局限**：
  - 缓存（LRU/LFU/FIFO）、预测式预取、缓存感知路由只能在路由允许的范围内起作用；当请求间专家复用度低时，小缓存仍频繁缺失，预取也难以完全掩盖传输开销。
  - 仅微调路由器（如 ReMoE）可重塑路由以复用专家，但**专家保持冻结**，无法适应被重定向过来的 token，限制路由集中度的上限。
- **研究切入点**：通过微调让 token 集中到更少的专家上，以在固定显存预算下提升复用率；但必须同时让这些专家适应新的 token 分布，否则精度会下降。

## 2. 方法论：MaskCoFT

### 核心思想
- 在每层引入**可学习的二值路由掩码**，把该层 Top-K 路由限制到一个所有 token 共享的「集中专家集」（concentration set），并**联合微调路由器与专家**。
- 训练只用交叉熵损失，不引入辅助的局部性或负载均衡损失，因此没有额外的损失超参数。
- 推理时把硬掩码替换为学到的软先验，对专家重新排序，**不排除任何专家**。

### 关键技术细节

**预备知识**：每层有 E 个路由专家与路由器权重 W，路由概率 p = softmax(Wx)，Top-K 激活集 A，输出 y = Σ_{i∈A} g_i F_i(x)。Mixtral 对门控权重在激活集上重归一化，DeepSeek-V2-Lite 直接用 p_i，并另有共享专家（共享专家不参与掩码）。

**Stage 1：压缩与搜索（Compact and search）**
- 每层维护实数掩码 m̃ ∈ R^E，初始化各元素相等；softmax 得采样分布 π（初始均匀 1/E）。
- 从 π 中**无放回多项式采样** E′ = r·E 个专家，得到恰有 E′ 个 1 的二值掩码 m；约束 K ≤ E′ ≤ E。
- 掩码内做 Top-K：π = softmax(m̃)，m = MultinomialSample(π, E′)，A = Top-K(p ⊙ m)。由于激活集上 m_i = 1，前向门控值与 Eq.(1) 一致，乘积项的作用在反向传播中为 m 提供梯度。
- **同一 batch 内所有 token 共享同一掩码**，且每步重新采样以探索不同集中集；路由器与专家每步更新，而实数掩码梯度累积 T 步后更新一次（对 T 个采样集取平均）。

**Stage 2：收敛与协同适应（Converge and co-adapt）**
- 待采样集稳定后固定每层的二值掩码与实数掩码，停止更新 m̃，继续微调路由器与专家。
- 路由器学习在固定集合内分配 token；原先由被掩蔽专家处理的 token 现在流向集合内专家，这些专家的 LoRA 适配器学习处理它们（论文称为 knowledge transfer to the concentration set）。

**掩码优化（不可微处理）**
- 采样不可微，采用**直通估计器（STE）**，反向把采样视为恒等；损失经激活专家的门控权重传到 m；因所有 token 共享掩码，∂L/∂m 汇总 batch 内所有 token 的贡献；再经 softmax 雅可比传到 m̃：∂L/∂π ≈ ∂L/∂m，∂L/∂m̃ ≈ (diag(π) − ππᵀ) ∂L/∂m。

**推理规则**
- A = Top-K(p ⊙ π)。π 各分量均为正，故构造上不排除任何专家；当某集合外专家的 p_iπ_i 进入前 K 时仍可被激活。先验只改变「哪些专家激活」，不改变门控权重（门控仍按 Eq.(1) 由 p 计算）。

## 3. 实验设计

- **模型**：Mixtral-8×7B（粗粒度，每层 8 个路由专家、Top-2）与 DeepSeek-V2-Lite（细粒度，每层 64 个路由专家 + 2 个共享专家）。
- **微调数据**：OpenHermes-2.5 多轮指令/对话语料，沿用 ReMoE 的预处理，采样 100K 训练、1K 验证。
- **容量基准（9 项）**：MMLU、ARC-E、ARC-C、HellaSwag、WinoGrande、PIQA、BoolQ（0-shot 多选）；GSM8K（5-shot，flexible-extract，另报 strict-match）；HumanEval（0-shot pass@1）。使用 EleutherAI LM Evaluation Harness。
- **缓存仿真**：从 ShareGPT V3 unfiltered 采样 128 条序列，贪心解码、batch size 1、最多 64 个新 token，记录每步所选专家；每层缓存 B 个专家（K ≤ B < E），缓存跨 prompt 持续、初始填充计为缺失；LRU/LFU/FIFO 三种淘汰策略；指标为命中率 HR 与 Fetches/tok，满足 Fetches/tok = LK(1 − HR)。主设置 B = 12（DeepSeek）/ B = 4（Mixtral），并做预算消融 B ∈ {12,24,36} 与 {2,4,6}。
- **真实系统测量**：在 MoE-Offloading 中服务，用 NVIDIA Nsight Systems 剖析；从 ShareGPT V3 选 32 条长度 ≥128 的 prompt 并截断到前 128 token，输出长度 64 与 128；报告 TTFT、TPOT、端到端吞吐。
- **对比方法**：Base（预训练基线）、CE-only（仅交叉熵微调，与 MaskCoFT 唯一差别是无掩码）、ReMoE（仅路由器微调，引用其报告数值）。
- **训练配置**：LoRA rank 8、alpha 16、dropout 0.05；专家与路由器用线性调度、峰值学习率 2e-4；掩码用余弦调度、峰值 0.05、下限比例 0.2；两个模型均用 compact ratio r = 75%；二值掩码每步重采样；实数掩码梯度累积 T = 100（DeepSeek）、T = 1（Mixtral）；DeepSeek 共 5000 步、Mixtral 共 3000 步；种子 42。

## 6. 主要结论与发现

- **取数下降**：在 LFU 缓存下（B = 4/12），每 token 专家取数相比 Base 减少 23.7%（Mixtral）与 10.1%（DeepSeek）；在 LRU/LFU/FIFO 三种策略及所有测试预算下均保持优势。
- **实际加速**：真实卸载服务中 TPOT 最多降低 16.4%（Mixtral，128 输出 token）与 5.5%（DeepSeek）；吞吐提升 13.3%/9.5% 与 3.9%/5.7%；TTFT 变化不超过 4.4%（128-token prefill 几乎触及每层多数专家）。CE-only 在 Mixtral 上反而比 Base 慢 3.0%–6.0% TPOT。
- **精度保持**：9 基准平均精度比 Base 高 0.92（Mixtral）与 0.53（DeepSeek）个百分点；比 CE-only 低 1.22 与 0.46 个百分点。
- **粒度差异**：粗粒度 Mixtral 的集中效应更强（LFU 下 HR 增益 +9.10 vs +5.73 个百分点），因为掩码后候选专家池更小；细粒度 DeepSeek 在生成任务（GSM8K/HumanEval）上能匹配或超过 CE-only，而 Mixtral 落后约 2.2 分。
- **策略偏好**：LFU 下增益最大，说明 MaskCoFT 学到的是**全局稳定偏斜**（与输入无关、所有 token 共享的掩码）；ReMoE 在 LRU/FIFO 下增益更均衡，与其面向近邻 token 复用的时序局部性正则一致。
- **与 ReMoE 对比**：精度上 ReMoE 总体略优（明显差距在 MMLU，ReMoE 保持、MaskCoFT 掉 2.17 分）；LFU 命中率增益两者接近（+5.73 vs +5.54），LRU/FIFO 下 ReMoE 增益更大。MaskCoFT 额外训练了专家并做推理重排序，ReMoE 仅调路由器。

## 7. 优点

- **方法简洁**：只用交叉熵损失，不引入局部性或负载均衡辅助损失，无需调损失权重；直接指出负载均衡损失与「集中激活」目标相冲突。
- **训练与推理解耦设计巧妙**：训练用硬掩码强制集中，推理退化为软先验，理论上不排除任何专家，保留了路由的灵活性与精度下限。
- **非可微采样的处理规范**：STE + 梯度跨 T 步累积，使掩码更新对多个采样集取平均，并有附录中的集中集收敛曲线佐证（Mixtral 1.7k 步达 100%，DeepSeek 4.5k 步达 99%）。
- **验证层次完整**：trace 驱动仿真（多策略、多预算）与真实卸载系统测量（Nsight 剖析、TTFT/TPOT/吞吐）互相印证，并给出解码延迟分解。
- **对照设计有意识**：CE-only 作为同损失、同数据的强对照，有效把掩码贡献从微调收益中剥离。
- **跨粒度泛化**：在粗粒度与细粒度两种 MoE 上均有效，并给出机制层面的解释。

## 8. 不足与局限

- **精度存在回退**：相比 Base，DeepSeek 的 MMLU 掉 2.17 分；Mixtral 的 GSM8K 掉约 2.2 分（相对 CE-only），说明掩码限制对推理类任务有代价，论文用「几个测试题」淡化，但未做统计显著性分析。
- **对比公平性受限**：ReMoE 无代码/checkpoint，shot 数与种子未公开，只能各自与自身 Baseline 比；作者亦承认 Baseline/CE-only 数值差异可能源于这些未报告设置。
- **实验覆盖偏窄**：仅 2 个模型、1 个微调数据集（OpenHermes-2.5）、单一种子 42；未评估多语言、长上下文（32K 上下文未测试）、多轮长对话等场景；未与 StickyMoE、Oracle-MoE、cache-aware routing 等训练类方法直接对比。
- **超参数敏感性未探究**：compact ratio 固定 r = 75%，未报告 r 与 K、E′ 关系对精度/取数的权衡；T 在模型间相差 100 倍且无解释；掩码学习率 0.05 远高于常规，缺少敏感性分析。
- **机制层面的隐忧**：STE 是有偏近似；掩码与专家协同适应可能加剧专家间的功能退化（专家多样性下降），论文未分析长期影响；训练时需要同时更新路由器与专家（LoRA），训练成本高于仅调路由器，但未报告额外训练开销。
