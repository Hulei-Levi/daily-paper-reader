## 摘要
混合专家（MoE）预训练依赖于辅助负载均衡损失（LBL）来推动每个专家的利用率趋于均匀。后训练则继承了不同的情况：基础路由器已经编码了非均匀的专家共激活结构，而重新施加的均匀性目标会将其抹平。我们表明，下游性能反而依赖于柔和地保持这种继承的路由，我们将这一原则称为软路由器锚定，并将其实例化为路由器先验偏差（RPB），这是一种训练时偏差，将路由器逻辑向从冻结的基础路由器读取的先验拉近，同时使路由器本身保持可训练。在Moonlight-16B-A3B的数学后训练中，RPB获得了45.77的域内准确率，而重新应用LBL时为31.91，无锚定微调时为29.44，并且在域外能力上保留得比两者都多。与LBL的排序在第二个模型家族（Qwen3-30B-A3B-Base）上重现，并且对LBL的优势可在独立来源的语料库上得到验证。定义在路由器权重、其逻辑或其输出分布上的锚定表现相当，没有一致的排序，这表明效果在于约束的柔和性，而非RPB提供的特定先验。在专家共激活图中保留的社区结构追踪了这些收益，只要基础路由器足够不均匀以至于能形成社区，然而将相同的先验强制为硬赋值会保留该结构，但性能急剧下降。因此，社区结构是软锚定的足迹而非其来源，实际教训是，在后训练期间应柔和地保持继承的路由，因为既将其向均匀性抹平又绝对地强制它都会带来下游成本。我们的代码将在https://github.com/naver-ai/rpb发布。

## Abstract
Mixture-of-Experts (MoE) pretraining relies on an auxiliary load-balancing loss (LBL) to drive per-expert utilization toward uniformity. Post-training inherits a different situation: the base router already encodes non-uniform expert co-activation structure, which a re-imposed uniformity objective flattens away. We show that downstream performance depends instead on holding this inherited routing softly, a principle we term soft router anchoring, and instantiate it as Router Prior Bias (RPB), a training-time bias that pulls the router logits toward a prior read off the frozen base router while leaving the router itself trainable. On math post-training of Moonlight-16B-A3B, RPB attains 45.77 in-domain accuracy against 31.91 under re-applied LBL and 29.44 under unanchored fine-tuning, and retains more out-of-domain capability than either. The ordering against LBL reproduces on a second model family (Qwen3-30B-A3B-Base), and the advantage over LBL is resolvable on an independently sourced corpus. Anchors defined on the router weights, on its logits, or on its output distribution perform comparably with no consistent ordering, which places the effect in the softness of the constraint rather than in the particular prior RPB supplies. Retained community structure in the expert co-activation graph tracks these gains wherever the base router is non-uniform enough for communities to form, yet enforcing the same prior as a hard assignment preserves that structure while performance falls sharply. Community structure is therefore a footprint of soft anchoring rather than its source, and the practical lesson is that inherited routing should be held softly during post-training, since both flattening it toward uniformity and enforcing it absolutely carry a downstream cost. Our code will be released at https://github.com/naver-ai/rpb.

## 1. 核心问题与研究动机

**背景与问题：**
- 混合专家（MoE）模型在预训练期间通过辅助负载均衡损失（LBL）强制各专家利用率趋于均匀，以充分利用大规模参数。
- 但在模型进入后训练阶段时，路由器已经学到了非均匀、具有结构性的专家协同激活模式（即某些专家倾向于被同一 token 共同选择）。
- 此时若在后训练中重新施加均匀化目标（LBL），会破坏预训练阶段已经建立的路由结构，造成下游任务性能下降。
- 现有实践（如 NVIDIA Megatron Bridge 移除负载均衡、Unsloth 冻结路由器层）虽然已直觉上避开均匀化，但对于"继承的基础路由结构应保留什么、如何保留、保留到什么强度"这三个问题，仍缺乏系统性的实验分析。

**核心科学问题：**
> MoE 后训练中，应当以何种方式、何种强度来保留基础路由器已学习到的路由结构？

## 2. 方法论

### 2.1 核心思想：软路由器锚定（Soft Router Anchoring）

- 继承路由应当被**柔和地保持**（softly held），而非：
  - 被均匀化目标（LBL）抹平；
  - 或通过冻结/硬性赋权被绝对锁死。
- 路由器的参数本身仍应可训练，以便适应后训练语料。

### 2.2 三种路由保留度量层级

| 层级 | 度量 | 描述 |
|------|------|------|
| 逐专家利用率 | TVD / JSD | 经典 LBL 所针对的边际负载分布 |
| Token 级 top-k 选择 | top-k overlap | 同一 token 在基础与后训练路由下的 top-k 重合度交叉数 |
| 专家共激活社区结构 | 社区 NMI（层平均） | 通过 Louvain 社区检测度量共激活图划分的保留程度 |

其中专家共激活图构建流程：对每个 token 统计被同时选择的专家对 → 累积为逐层加权的专家共激活图 → 按保留边比例（默认 0.10）阈值化 → 用 Louvain 社区检测 → 计算与基础分区之间的 NMI。

### 2.3 Router Prior Bias（RPB）

核心流程：
1. **冻结基础路由器的先验统计**：对每个训练样本 x，按其语义区域分为 Q（指令/提示）与 A（回答）两个 span，对每个 span 中的 token 在冻结基础路由器上的 softmax 门控概率取平均，得到每个专家被选择的先验频率 π。
2. **零均值对数偏置**：将先验经 clip 截断（防止 log 爆炸），取对数并沿专家维度减去均值，得到零均值的对数偏置 b。
3. **训练时注入**：对 span 内所有 token 的路由 logits 加入 β·b（β 为干预强度系数），再经过 top-k 选择。β=0 时退化为普通 SFT。
4. **评估时移除偏置**，使测得的拓扑结构反映训练后路由器本身的真实行为。

### 2.4 其他锚定方法（对照）

- **Router-L2**（参数空间锚定）：对路由器权重矩阵施以 L2 惩罚，使其接近冻结的基础权重，但路由器保持可训练，无需样本条件先验。
- **KL-to-base**（概率空间锚定）：以冻结基础先验为目标对当前路由器输出分布做 KL 散度损失。
- **Logit-L2**（中心化 logit 空间锚定）：对中心化后的 logits 与中心化的基础 log-prior 做 L2 距离。

### 2.5 对照干预

- **RPB-hard**（硬性赋权控制）：用 clip 后的对数先验直接替换路由 logits，作为 top-k 选择的唯一分数，消除 token 条件路由，等同于硬性锚定。
- **within-soft**（社区内置换、软应用）：仅在同一检测社区内部置换专家身份，先验内容被破坏但社区保留，并仍以软偏差形式施加。
- **within-hard**（社区内置换、硬应用）：同一社区内置换 + 硬性 top-k 强制。
- **global-hard**（跨社区置换、硬应用）：跨社区全局置换 + 硬性 top-k 强制。
- 该 2×2 设计（置换范围 × 强制强度）将"先验内容"和"约束强度"两个维度解耦。

## 6. 主要结论

### 核心发现 1
在后训练期间应用 LBL 比在 MoE 引导参数固定的情况下应用它会严重降低性能。
- Moonlight math：RPB 45.77（ID）-> LBL 31.91 -> SFT 29.44。
- LBL 的相对劣势在 Qwen3-30B 和 OpenR1 上均有复现：10.20 点的 LBL 相比 RPB 差距。

### 核心发现 2
该效应可归因于约束的**柔和性（softness）**，而不是锚的具体形式，因为四种不同的锚定目标（参数/对数/logit-空间）效果相近，且各空间的最优性在不同的语料下会互相重叠。

### 核心发现 3
社区 NMI 是能够区分*软锚定*与 LBL 的诊断指标（per-expert 的 TVD/JSD 无法区分，top-k overlap 对 SFT 和锚定方法之间有所交叠）。
- 但：这并非一个需要最大化的目标。
- RPB-hard 的社区 NMI 高于 RPB，而性能却低于 RPB。
- *社区结构是训练的踪迹，而非绩效的来源。*

### 核心发现 4
用因果对照验证：在软锚定下，对社区内先验进行置换*不会*降低太多性能；在保持相同社区先验内容的情况下，改用硬约束则会导致性能显著下降。因此，起作用的是*强制强度的柔和性*，而非专家身份特定的先验。

### 核心发现 5
上述诊断仅在基础路由器已经形成可辨识的社区时才起作用。

### 实际启示
在 MoE 后训练期间，应柔和地锚定*继承的协同激活结构*，而非：
- 扁平化并均匀化专家负载；
- 将路由器和/或专家选择完全硬冻结。

## 7. 优点与亮点

1. **问题选择精准**：识别了社区的实践混淆，而这些人此前只是在默认上没有 LBL，而未弄清"是哪一个"在其中起作用。
2. **方法论具备解耦性**：通过 2×2 设计（先验内容 × 强制强度）分离出可区分的关键变量，**锚定强度才是核心因素**。
3. **精细的多层级路由指标**（而非简单对照 base-route 匹配）：
   - L1/TVD，JSD；
   - top-k overlap；
   - 社区 NMI，并配备零模型、模块化验证、阈值和分配器扰动。

4. **使用无推断时的偏置协议**：报告推理时去除所有训练相关 hook 的指标——保证了与真实部署的一致性。
5. **诚实报告负面结果**：利用其"弱点"完成一个深度的消融问题——关于无锚定基线的优势是模型依赖的：注意 Qwen coding20k 中 NoAux 胜过 RPB 的情况。
6. **在三个粒度（内容、强度、跨模型/语料）都提供了广泛的控制**来验证机制的显著性。

## 8. 不足与局限性

**主要缺点：**

1. **现有模型依赖的适用范围**：
   - 社区/诊断路径仅针对 Moonlight 有效，而对 DeepSeek 和 Qwen 为弱失效版/失效版。
   - 没有扫描路由分布 sharpness 并证明诊断在何种阈值下渐次失效。
   - 作者自己也承认"未指出哪个属性预测了性能方向"——甚至在 Qwen 的零模型的缺乏上也不够明确。

2. **缺少对社区内部组织的描述**：来自 "Louvain 社区与专家身份"的结论——实际并未验证社区的语义一致性，即使是关于内部组成上也是如此。

3. **消解的泛化性不强**：对比基线的角度有限——数学/编程二领域二元语料来自同一个数据源 GLM-5.1-Reasoning-1M-Cleaned。目前不清楚混入更多语料（指令/多域）时参数的偏移或 β 的表现会怎样。

4. **计算成本**：需要大量资源（16 个节点 H200），重复若干使用多跨度 E2E 相关的研究。对从业者而言，限制使用范围较广。

5. **跨空间的结论有限制：没有任何单一目标在所有情况下胜出**：
   - 在 5.1.2 表中，所列基线之间的差异可能因语料不同而反向翻转... 表明所选内核/空间也许存在未调谐到最优的差异，但原因尚未充分揭示。

6. **无推理模型，只有问答对**：没有通过长期 CoT 推理提高效果的情况（所有数据均非推理型、基于 QA）。作者给出的是具体的"transitions"概念——通过顺序的推理步骤追踪，但并未将其纳入研究范围内，因此留下了剩余的变化来说明长期解释。

7. **原因-目标纠缠**：*未测试*任何可用于解释为何 RPB-hard 保留社区但失效的实际理论机制。区分了贡献，但并未深入解释其实现的原理。

8. **知识保留的评估范围尚窄**：此外，同时引入评估指标方式仍偏窄——仅测量数学/编程能力（虽已包含 12 个 benchmark，但方向性的领域能覆盖较窄），且并未测量更广会话、工具使用或推理能力的表现。
