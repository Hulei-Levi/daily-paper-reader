## 摘要
混合专家（MoE）架构通过为每个令牌激活稀疏的专家子集，高效地扩展了大语言模型（LLM）的能力。然而，现代MoE推理仍然受到刚性的整体专家抽象的严重制约。现有框架将专家视为原子执行单元进行管理、调度或剪枝，这过早地固定了优化边界，并使得细粒度的专家内计算冗余未被充分探索。在这项工作中，我们提出了PCoMoE，一个路径组合执行框架，将MoE推理从粗粒度的专家选择转变为细粒度的路径组合。PCoMoE包含路径级的专家计算公式、一种兼容性感知的逐层剪枝策略以抑制低价值路径组合，以及一个硬件友好的执行引擎，以在严格有界的开销下利用可重用的子专家结构。实验结果表明，PCoMoE实现了高达1.31倍的端到端推理加速，同时将模型准确率提高了10%。代码可在 https://github.com/gzyyy0/PCoMoE 获取。

## Abstract
Mixture-of-Experts (MoE) architectures scale Large Language Model (LLM) capacity efficiently by activating a sparse subset of experts per token. However, modern MoE inference remains heavily constrained by the rigid, whole-expert abstraction. Existing frameworks manage, schedule, or prune experts as atomic execution units, which fixes the optimization boundary too early and leaves fine-grained intra-expert computational redundancy underexplored. In this work, we present PCoMoE, a path-compositional execution framework that shifts MoE inference from coarse-grained expert selection to fine-grained path composition. PCoMoE incorporates a path-level formulation of expert computation, a compatibility-aware layer-wise pruning strategy to suppress low-value path combinations, and a hardware-friendly execution engine to exploit reusable sub-expert structures under strictly bounded overheads. Experimental results demonstrate that PCoMoE achieves up to a 1.31x end-to-end inference speedup while enhancing model accuracy by 10%. The code is available at https://github.com/gzyyy0/PCoMoE

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **MoE 架构的困境**：混合专家（Mixture-of-Experts, MoE）架构通过为每个 token 仅激活稀疏的专家子集，实现模型容量的高效扩展，已成为现代大语言模型（LLM）高吞吐服务的关键基石。然而，**理论上的计算稀疏性并不能自动转化为端到端的系统效率**。
- **现有优化的根本局限**：当前主流优化框架（调度、缓存、卸载、专家级剪枝与复用等）均从**专家间（inter-expert）**视角出发，将每个专家视为**不可再分的原子执行单元**。这种粗粒度的整体专家抽象过早地固定了优化边界，使专家内部（intra-expert）的细粒度计算冗余——例如 SwiGLU 结构中扩张侧（gate/up）与投影侧（down）之间在计算成本和语义角色上的显著不对称——长期未被探索。
- **核心问题**：能否打破"专家作为一个整体被选择或跳过"的二值约束，将计算冗余的挖掘深入到专家内部，实现更优的效率—质量权衡？
- **PCoMoE 的答案**：将 MoE 推理从"专家选择"范式转变为**细粒度路径组合（path composition）**范式，在不新增参数、不破坏原有 MoE 层接口的前提下，利用子专家结构的重组与复用，同时提升推理速度与模型质量。

## 2. 论文提出的方法论

### 2.1 核心思想：路径组合（Path Composition）

PCoMoE 利用 SwiGLU 型专家内部固有的**扩张—投影结构边界**，而非任意算子级拆分：

- **扩张侧** $U_e(h)$：由 gate 和 up 两个并行的线性投影（占专家总计算量的约三分之二）加 SiLU 激活与逐元素相乘构成：
$$U_e(h) = \text{SiLU}(W_{gate}^{(e)} h) \odot (W_{up}^{(e)} h)$$
- **投影侧** $D_e(z)$：单一的 down 投影（占总计算量约三分之一）：
$$D_e(z) = W_{down}^{(e)} z$$
- **路径定义**：将任意一个扩张侧源 $i$ 与投影侧目标 $j$ 组合为一条路径 $P_{i,j}(h) = D_j(U_i(h))$，从而将搜索空间从 $n$ 个物理专家扩展到 **$n \times n$ 的虚拟路径矩阵**：
  - **对角线路径** $(i,i)$ 即原始的专家 $F_i$，保持基线可用；
  - **非对角线路径** $(i \neq j)$ 是零参数开销的全新合成轨迹。

### 2.2 关键技术：兼容性感知的路径路由与逐层剪枝

路径空间的组合爆炸需要主动抑制低价值候选：

- **分解式路径打分**：每条路径 $(i,j)$ 的综合得分分解为三个可解释部分：
$$s_{i,j}^{(\ell)}(h) = g_{base,i}^{(\ell)}(h) + b_{i,j}^{(\ell)} + \lambda\, g_{tgt,j}^{(\ell)}(h)$$
  - $g_{base}$：锚定预训练 checkpoint 的源侧路由先验；
  - $b_{i,j}$：可学习的**兼容性偏置矩阵**，刻画扩张源与投影目标之间的结构对齐程度；
  - $g_{tgt}$：目标侧（投影）偏好先验。
- **保护基线的初始化**：对角线置零（$b_{i,i}=0$），非对角线初始化为负偏置加有界噪声（$b_{i,j} \sim c + \epsilon, c<0$），优先保证原始专家行为不被初始的无约束重组破坏。
- **迭代结构剪枝**：通过训练阶段的渐进式稀疏化生成逐层活动掩码 $M^{(\ell)}$（对角线恒为 1），将剪枝视为路由资格约束而非物理参数删除。不同层根据局部敏感度收敛到各自的路径密度，抑制低价值非对角线路径同时保持表示保真度。保证推理时在线路由只评估一个紧凑的活跃路径集合，成功控制调度开销。

### 2.3 硬件高效执行引擎

将算法灵活性转化为物理加速的两个阶段：

1. **组合路径路由**（离线缓存 + 在线轻量索引）：基于剪枝后的活动掩码，离线物化路径索引和分组元数据；在线将过滤、Top-k 选择、分发准备融合为单次轻量索引操作，避免重建完整的 $n \times n$ 路径空间。因所有对角线路径保持活跃，路由天然可回退到低置信度场景下的 vanilla MoE 执行。
2. **源分组计算复用**（Source-Grouped Compute Reuse）：将分发单元从单个路径 $(i,j)$ 变为**源分组**——所有共享同一扩张侧算子的路径被合并调度。同一扩张算子 $U_i(h)$ 对每个唯一源只执行一次，其输出被动态分发到多个投影目标。扩张侧的计算量因此与活跃源数量 $|S|$ 成正比，而非路径总数 $|\Pi|$：
$$y = \sum_{i \in S(h)} \sum_{j \in T_i(h)} \beta_{i,j}(h)\, D_j(U_i(h))$$

## 6. 论文的主要结论与发现

1. **效率显著提升**：PCoMoE 最高实现约 **1.31× 端到端推理加速**、**1.305× 解码加速**（Mixtral-8x7B 解码吞吐从 26.50 提升到 34.58 tokens/s，端到端从 133.43 提升到 172.72 tokens/s）；在 Qwen1.5-MoE 上吞吐提升超过 20%。
2. **质量同步提升而非折损**：PCoMoE 在所有三个模型上均一致超越 Vanilla 与 Vanilla-FT。在 Qwen1.5-MoE 上，宏平均准确率从 Vanilla 的 67.90 提升至 73.70（+5.80 点）；相对 Vanilla-FT 最高提升 +2.87 点（DeepSeek-V2-Lite），显示激活的非对角线路径构成有效的表示轨迹。注意：标题摘要声称"准确率提升 10%"主要对应特定任务的相对增益，在宏平均绝对精度上提升约为 2–6 个百分点，读者应区分"10%"为相对提升率（如 Qwen1.5-MoE 上 5.8/67.9≈8.5%，Mixtral 上 2.1/77.9≈2.7%，综合论文口径可能有夸大）。
3. **扩张侧是结构性共享的最佳边界**：扩张侧在计算上占主导（三分之二 FLOPs）且具有更好的结构容忍性，投影侧替换代价更低——验证了扩张—投影边界作为优化抽象的有效性。
4. **局部容忍不等于全局安全**：单层专家剪枝的跨层差异显著，多层叠加会使局部误差灾难性累积，因此需要逐层敏感度的差异化路径剪枝而非统一剪枝。
5. **剪枝分布具有层级模式**：Qwen1.5-MoE 上，前两个 MoE 层保持密集路径（兼容性偏置不可分离），从第三层开始活跃路径急剧收缩。各层计算节省率呈现 15%–27% 的非均匀分布（均值 20.6%），支持逐层差异化路径预算分配的必要性。

## 7. 优点

1. **问题定位精准且新颖**：识别出"整体专家抽象过早固定优化边界"这一核心瓶颈，将 MoE 优化从粗粒度的专家选择推进到细粒度的路径组合，视角有原创性。
2. **结构洞察扎实**：利用 SwiGLU 专家天然的扩张—投影结构不对称（计算量 2:1、结构容忍度差异）划分组合边界，而非盲目算子级拆分，兼顾了优化空间与调度可控性，把握了一个"中间地带"。
3. **严格的兼容性设计**：
   - 对角线路径恒激活保证顶层设计兼容原模型，天然回退到 vanilla MoE；
   - 兼容性矩阵的负偏置初始化保护预训练行为；
   - 零参数开销——所有路径仅重排已有算子。
4. **硬件软件协同（软硬协同）**：源分组复用直接降低计算密集的扩张侧执行次数，路径索引融合避免在线构建稠密矩阵，使路径灵活性真正落地为端到端加速。
5. **实验验证较完整**：3 个模型、5 个任务、多组消融、逐层敏感性分析、执行级累积加速分解，证据链有一定的系统性，不是"单点报告式"。

3. **实验细节披露不足（最为关键）**：报告中缺乏训练 epoch、学习率、单卡训练时间、吞吐测量的 batch size/序列长度/K 值、多次运行方差等信息，第三方难以精确复现或推断其在不同负载下的稳定性。
4. **对比公平性存疑**：与 MoE-I²、MoE-Pruner、MoEITS 等基线的方法对齐说明太少（是否同数据微调、是否同 LoRA 配置），而基线成绩反常地显著低于 Vanilla，削弱了质量对比的客观性；同时缺少与这些方法在相同解码阶段的吞吐对比，效率优势的证据链条不完整。
5. **质量度量维度窄**：仅在 5 个英文零样本常识/问答任务上评估，未覆盖对话、代码、数学推理、多语言等场景；使用困惑度（PPL）做分析但下游报告使用准确率，两者关系未明确讨论。
6. **10% 准确率提升的表述存在夸大风险**：摘要宣称"enhancing model accuracy by 10%"，若按宏平均准确率理解，三个模型相对 Vanilla 的绝对提升为 +2.10~+5.80 点（相对 2.7%~8.5%），不足 10%；若按相对误差减少率或特定任务相对提升计算则可能接近 10%，但正文未清楚交代口径，存在表述模糊之处。
