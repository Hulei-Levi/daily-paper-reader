## 摘要
在这项工作中，我们介绍了 Instella-MoE，一个完全开放的混合专家（MoE）语言模型，总参数为160亿，每个 token 的活跃参数为28亿，完全从头开始在 AMD Instinct MI300X 和 MI325X GPU 上训练。Instella-MoE 将稀疏激活的 MoE 设计与架构和系统级创新相结合，包括门控多头潜在注意力（Gated MLA）和 FarSkip-Collective 连接，实现了高效的大规模训练和推理。该模型通过多阶段流程开发，包括预训练、中期训练、长上下文扩展、基于反馈驱动数据整理的监督微调、直接偏好优化，以及使用多教师在线策略蒸馏的强化学习。Instella-MoE 在标准预训练基准上平均得分为76.7，优于先前的完全开放模型，包括 OLMo-3-7B、SmolLM3-3B 和 OLMoE-1B-7B，同时与具有可比活跃参数规模的开权重 MoE 和密集基线模型（包括 Moonlight-16B-A3B 和 Qwen3.5-4B）相比保持竞争力。在后训练之后，我们的最终 Think 检查点在指令遵循、推理、数学、编码和聊天基准上平均得分为73.2，在我们的评估中优于具有可比或更大活跃参数数量的完全开放和开权重模型。为了支持透明和可重复的研究，我们发布了完整的 Instella-MoE 模型流程，包括模型权重、训练配置、数据混合和训练代码。总之，这些贡献使 Instella-MoE 成为高效、高性能 MoE 模型和可重复研究的强大、完全开放的基础。

## Abstract
In this work, we introduce Instella-MoE, a fully open Mixture-of-Experts (MoE) language model with 16 billion total parameters and 2.8 billion active parameters per token, trained entirely from scratch on AMD Instinct MI300X and MI325X GPUs. Instella-MoE combines a sparsely activated MoE design with architectural and system-level innovations, including Gated Multi-head Latent Attention (Gated MLA) and FarSkip-Collective connectivity, enabling efficient large-scale training and inference. The model is developed through a multi-stage pipeline comprising pre-training, mid-training, long-context extension, supervised fine-tuning with feedback-driven data curation, direct preference optimization, and reinforcement learning with Multi-Teacher On-Policy Distillation. Instella-MoE achieves an average score of 76.7 across standard pre-training benchmarks, outperforming prior fully open models including OLMo-3-7B, SmolLM3-3B, and OLMoE-1B-7B, while remaining competitive with open-weight MoE and dense baselines at comparable active-parameter scales, including Moonlight-16B-A3B and Qwen3.5-4B. After post-training, our final Think checkpoint achieves an average score of 73.2 across instruction-following, reasoning, math, coding, and chat benchmarks, outperforming both fully open and open-weight models with comparable or larger active parameter counts in our evaluation. To support transparent and reproducible research, we release the complete Instella-MoE model flow, including model weights, training configurations, data mixtures, and training code. Together, these contributions establish Instella-MoE a strong, fully open foundation for efficient, high-performing MoE models and reproducible research.

- **核心问题**：此前完全开放的 MoE 模型（如 OLMoE-1B-7B）虽然验证了开放路线可行性，但在性能上相对开放权重模型仍存差距，且尚无基于 AMD GPU 大规模构建全开放 MoE 模型的成功先例，缺乏同时兼顾开放性、性能与硬件适配性的强基线。
- **本文回应**：提出 **Instella-MoE**，一个“完全开放”的 MoE 模型（16B 总参数、2.8B 激活参数），在 AMD MI300X/MI325X 上从零训练，从权重到代码、数据配方全面开源，旨在证明“透明度与高性能可以共存”。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程
### 2.1 核心思想
采用稀疏 MoE 架构，以 2.8B 的激活参数获得接近更大密集模型的表达能力，并通过架构和系统级创新突破 MoE 的通信瓶颈，在 AMD 平台上实现高效训练与推理；同时用完整的、逐阶段公开的多阶段训练管线保证可复现性。

### 2.2 架构创新（两大核心技术）
- **Gated Multi-head Latent Attention（Gated MLA）**：
  - 基于 DeepSeek 的 MLA 低秩 KV 压缩（降低 KV 缓存占用），引入“输入条件化输出门”。
  - 用 Sigmoid 门逐通道调制注意力输出后，再经输出投影：$y_t = W_o(\text{Sigmoid}(W_g x_t) \odot \hat{o}_t)$。
  - 作用：提升模型表达力；消融显示在 200B-token 预算下较 Vanilla MLA 提升 0.47 平均分（49.86→50.33），尤其受益于 MMLU 与代码生成。
- **FarSkip-Collective 连接（通信-计算重叠）**：
  - 核心问题：标准 MoE 的 **Dispatch** 必须等前层输出，**Combine** 的输出又是下一层注意力的依赖，导致两个 all-to-all 通信无法与计算重叠。
  - 解决方案：修改层间连接顺序，将路由专家结果（routed experts）从注意力输入中“跳过”（仅将部分激活作为注意力输入），使得 **Dispatch 与注意力计算重叠**、**Combine 与共享专家计算及注意力前半段重叠**；传播延迟最多为一个层。
  - 核心公式思想：$h_{k+1} = h_k + f_{k+1}(\hat{h}_k)$ 即用可用激活（部分/过期激活）推进下一层计算，同时通信并产生完整 $h_k$。
  - 收益：预训练吞吐率提高 **12.7%**；SGLang 专家并行下 TTFT 吞吐率提升 **39.2%**；在 200B-token 消融下精度与标准连接持平（50.38 vs. 50.33）。

### 2.3 多阶段训练流程（七个阶段）
| 阶段 | 数据量/规模 | 关键设置 |
|---|---|---|
| ① 预训练 | 7.1T tokens，4K 上下文 | WSD 调度（峰 4e-4）、MTP 辅助目标（权重 0.3）、FarSkip、EP=8 |
| ② 中期训练 | ~100B tokens | 三变体 + 等权 model soup，STEM/推理强化，LR 2e-4，MTP 降权 0.1 |
| ③ 长上下文扩展 | Stage1 ~194B + Stage2 ~20B，64K 上下文 | YaRN（θ=8e6）、文档掩码；先长文档适配，再用 37.32B STEM 混合恢复短上下文能力 |
| ④ SFT | ~2.9M 示例，两阶段 | 阶段一用 Dolci-Think + 数学/代码/科学定向；阶段二用 512K“反馈驱动数据策展” |

### 2.4 SFT 阶段“反馈驱动数据策展”机制
- 三步线：**诊断**（用 LLM-as-judge 对学生错误做结构化错误分析）→ **查询生成**（反思模型将错误聚合成加权检索 query）→ **检索**（按 embedding 相似度为每个 query 取回近邻样本，辅以随机同域采样填充）。
- 效果：在同等 512K 预算下较均匀采样提升 **1.5 分**，IFEval +4.8、AIME25 +3.6、LCB +3.2。

## 7. 优点
- **真正的“完全开源”而非“开放权重”**：从预训练到 RL 的每个阶段权重、数据配方、超参数、代码全部公开，为学术社区提供极高的可复现价值，特别是在非 NVIDIA 平台上。
- **架构创新具有实际意义**：Gated MLA 将门控机制与 MLA 低秩缓存结合，兼顾显存效率与表达能力；FarSkip-Collective 直接解决 MoE 大规模训练中通信占空比的痛点，而非依赖定制 kernel，设计轻巧、可移植性强。
- **对 MoE 特有问题的细致诊断**：
  - 识别 MoE 在 DPO 阶段对负载均衡的敏感性（路由稳定性从 0.42 提升至 0.94）；
  - 引入 Rollout Routing Replay 解决训练/推理路由不一致；
  - 使用域路由式多教师蒸馏避免强化学习中的灾难性遗忘。
- **数据策展反馈闭环**：自诊断失败→聚类检索的 SFT 数据选择机制是一个可复用的范式，优于均匀抽样 +1.5 平均分。
- **长时间上下文训练方案**（长文档适配→STEM 恢复）作为通用 base-model 制造配方有参考价值。

## 8. 不足与局限
- **“完全开放”的边界仍待明确**：虽然称“fully open”，但训练数据主要来自 Nemotron-CC、Dolma 等第三方数据集，这些语料各自许可证不同，用户在下游商用/学术使用上仍需自行逐项核验。
- **实验统计强度不足**：关键的架构与 RL 消融均为单次运行、无随机种子重复，结论的统计稳健性未被验证；部分对比基线的成绩数值可能来源于各自原先的报告协议而非统一测评代码，横向可比性有限。
- **长上下文评测覆盖有限**：Stage2 的 STEM 恢复导致长文本能力下降（HELMET 43.7→41.5，RULER 83.9→79.4），这可能影响“通用长文本”场景的表现；且仅用 RULER/HELMET 两类合成/检索任务，未覆盖“大海捞针”之外更多面向真实长篇文档下游任务的场景（如法律/学术综述 QA）。
- **硬件投入信息不透明**：未公布总训练计算量、GPU 数量、有效吞吐（MFU）或碳排放等指标，外部难以评估其训练成本与“高效”声明的具体量化基准。
- **“Think”模型定位略尴尬**：MOPD 作为最终阶段，IFEval 得分（83.7）仍未完全追平 IF 专用专家（84.1），且 GPQA 相对 DPO 阶段略有下降（62.7→61.2），说明融合并非完全无损。
- **未涉及多模态、工具调用与安全性测试**：模型为纯文本架构，论文对事实性/毒性/偏见等安全评价完全没有披露。
