## 摘要
内存高效的矩阵优化器（如Sinkhorn梯度下降）为稠密Transformer矩阵移除了大部分AdamW优化器状态，但直接应用于混合专家（MoE）训练并不可靠。我们在一个受控的110M参数nanowhale DeepSeek风格MoE预训练设置中研究了这一失败。SAGE/Sinkhorn混合方法将优化器状态从0.883GB减少到0.331GB，但评估损失退化到3.8265，远高于我们在相同设置中观察到的AdamW基线（在我们研究的种子中为3.58–3.64）。我们表明，路由的MoE专家矩阵是主要失败点：其梯度是条件性的、随时间变化的，而无状态的Sinkhorn归一化难以有效处理。我们提出了MESH，一种用于MoE专家的隐藏动量Sinkhorn更新。MESH通过梯度缓冲区生命周期恢复时间一阶矩信号，而无需将专家一阶矩作为优化器状态存储。MESH还有可选的分块预条件变体，添加了粗粒度的神经元/分块逆RMS乘子。在消融实验中，矩阵归一化之前的时间平滑是主要因果因素；分块/神经元预条件可以改善内存-质量前沿，但并未被证明是普遍必需的。在两个额外的种子中，MESH和MESH-B相对于AdamW将优化器状态内存减少了62.5%，峰值PyTorch CUDA分配减少了约12.6%，而评估损失差异不大。全状态诊断变体在消融实验中恢复了类似AdamW的性能，支持了MoE专家需要时间平滑但不一定需要完整坐标级AdamW状态的结论。

## Abstract
Memory-efficient matrix optimizers such as Sinkhorn gradient descent remove most AdamW optimizer state for dense Transformer matrices, but direct application to Mixture-of-Experts (MoE) training is unreliable. We study this failure in a controlled 110M-parameter nanowhale DeepSeek-style MoE pretraining setting. A SAGE/Sinkhorn hybrid reduces optimizer state from 0.883GB to 0.331GB but degrades evaluation loss to 3.8265, far above the AdamW baselines observed in the same setup (3.58--3.64 across the seeds we study). We show that routed MoE expert matrices are the dominant failure point: their gradients are conditional, temporally varying, and poorly served by stateless Sinkhorn normalization. We propose MESH, a hidden-momentum Sinkhorn update for MoE experts. MESH restores a temporal first-moment signal through the gradient-buffer lifecycle, without storing the expert first moment as optimizer state. MESH is an optional block-preconditioned variant that adds a coarse neuron/block inverse-RMS multiplier. Across ablations, temporal smoothing before matrix normalization is the primary causal ingredient; block/neuron preconditioning can improve the memory-quality frontier, but is not established as universally necessary. In two additional seeds, MESH and MESH-B reduce optimizer-state memory by 62.5\% and peak PyTorch CUDA allocation by about 12.6\% relative to AdamW, with a modest evaluation-loss gap. Full-state diagnostic variants recover AdamW-like performance in ablations, supporting the conclusion that MoE experts need temporal smoothing, but not necessarily full coordinate-wise AdamW state.

- **研究背景**：大规模语言模型预训练中，AdamW 是默认优化器，因为它结合了时间一阶矩平滑与坐标级自适应缩放，但代价是每个参数需要存储两个完整的状态张量，内存开销巨大。为此，研究人员提出了内存高效的矩阵优化器，如 Sinkhorn 梯度下降，通过交替行/列归一化实现无状态更新，仅需保存梯度矩阵本身。SAGE 混合方案进一步将词汇表嵌入矩阵分配轻量状态、稠密矩阵留给 Sinkhorn。但这些方法主要针对稠密 Transformer 设计，尚未在 MoE 场景下得到验证。

- **核心研究问题**：Sinkhorn 类无状态优化器能否直接迁移到 MoE 语言模型训练？答案是**否定**。论文在 110M 参数的 nanowhale DeepSeek 风格 MoE 模型预训练中发现，直接采用 SAGE/Sinkhorn 混合方法虽可将优化器状态从 0.883GB 降至 0.331GB，但评估损失急剧恶化至 3.8265，远差于 AdamW 基线（3.58–3.64）。

- **问题根源的洞察**：MoE 中的路由专家矩阵虽然也是二维矩阵，但其梯度结构与稠密 MLP 梯度有本质区别。每个专家仅接收路由选择的 token 子集，且受门控分数加权，梯度是条件分布下的样本，随路由决策和隐藏状态的变化而高度波动。Sinkhorn 是一种非线性操作，对瞬时噪声梯度先归一化再平均，与先平均再归一化在数学上不等价，导致路由噪声被非线性放大。

- **整体含义**：论文提出 MoE 专家优化需要时间平滑，但不一定需要完整的 AdamW 坐标级状态，为在 MoE 场景下设计内存高效的优化器提供了新的方向和实证依据。

## 2. 论文提出的方法论

### 2.1 MESH：隐藏动量 Sinkhorn 专家更新

- **核心思想**：在 Sinkhorn 矩阵归一化**之前**引入时间平滑的一阶矩信号。对路由专家矩阵，使用隐藏动量累积器 \( H_{e,t} = \beta_1 H_{e,t-1} + G_{e,t} \)，然后对 \( H_{e,t} \) 执行 Sinkhorn 归一化得到更新方向 \( U_{e,t} = \text{Sinkhorn}(H_{e,t}; K, \tau) \)。这是一个**先平均后归一化**的流程，与无状态 Sinkhorn 的**先归一化后平均**（实际上是瞬时归一化）形成鲜明对比。

- **关键实现技巧——"隐藏"动量**：专家一阶矩 \( H_{e,t} \) **不存储在优化器状态字典中**，而是通过梯度缓冲区生命周期来维护：
  - 优化器步骤完成后，将专家梯度缓冲区暂存为隐藏状态 \( H \)；
  - 下一次反向传播前，将衰减后的隐藏动量重新挂载到梯度槽位（\( p.grad \leftarrow \beta_1 H_{e,t} \)）；
  - 反向传播自动累加当前梯度，得到 \( H_{e,t+1} \)。
  
  这一"prepare-before-backward"生命周期在 Trainer/Accelerate/DDP 风格训练循环中是必要的，因为朴素的 `zero_grad` 桥接可能被包装模型的梯度清理绕过。

- **设计细节**：使用未归一化的动量累积器 \( H_t \)（而非 Adam 风格的 \( (1-\beta_1)G_t \) 缩放），因为 Sinkhorn 归一化和均值归一化分块乘子对全局缩放不变。诊断显示实现中每次优化器步骤约有一次 prepare 调用，缓冲区影子余弦接近 1，相对误差约 \( 10^{-8} \)。

### 2.2 MESH-B：可选分块预条件变体

- MESH-B 在 MESH 的基础上添加了粗粒度**分块/神经元逆 RMS 乘子**：
  - 对专家 w1/w3 矩阵使用行统计，对 w2 使用列统计；
  - 块统计量从平滑后的源矩阵 \( H_{e,t} \) 计算，而非单独的原始梯度流：\( V_{e,t} = \beta_2 V_{e,t-1} + (1-\beta_2)R(H_{e,t})^2 \)；
  - 乘子 \( Q_{e,t} = \text{clip}\left( \frac{(V_{e,t}+\epsilon)^{-p/2}}{\text{mean}((V_{e,t}+\epsilon)^{-p/2})}, q_{\min}, q_{\max} \right) \)；
  - 最终更新：\( W_{e,t+1} = W_{e,t} - \eta Q_{e,t} \odot U_{e,t} - \eta\lambda W_{e,t} \)。

### 2.3 全状态诊断变体

- 论文设计了 **MESH-FULL** 和 **MESH-B-FULL**，它们将 \( H_{e,t} \) 显式存储在优化器状态中，而非通过梯度缓冲区传播。这些变体仅用于**诊断**，用于隔离隐藏动量的系统工程效果与时间平滑的优化器效果。

## 6. 论文的主要结论与发现

1. **路由 MoE 专家是 SAGE/Sinkhorn 混合方法的主要失败点**：将路由专家单独转换为 AdamW 即可恢复大部分性能差距，而共享专家转换帮助较小；将专家全部分配到 SAGE 反而更差。

2. **核心缺失成分是时间平滑而非坐标级第二矩**：V-only、符号动量/狮优化器、因式分解-v 等变体均无法恢复性能，只有加入时间一阶矩（MESH 的隐藏动量）才能大幅改善。

3. **顺序问题——先平均后归一化 vs 先归一化后平均是关键机制**：由于 Sinkhorn 非线性，将瞬时梯度归一化会放大路由噪声；先对梯度历史做时间平均再归一化则能有效过滤噪声。

4. **隐藏动量可以在不增加优化器状态的前提下恢复一阶矩信号**：通过梯度缓冲区生命周期实现，工程诊断显示实现保真度高（余弦相似度≈1，相对误差≈\( 10^{-8} \)）。

5. **分块预条件（MESH-B）是增量改进而非必需**：在种子 100/512 中，无分块的 MESH 与 MESH-B 性能接近；仅在种子 42 的诊断中，分块预条件有明显收益。

6. **内存节省显著**：MESH/MESH-B 相对于 AdamW 减少 62.5% 的优化器状态内存和约 12.6% 的峰值 CUDA 分配，评估损失差距适中（约 0.05）。

7. **与 AdamW 的残余差距可能来自非专家角色分配**：词汇表矩阵（占总参数约 75%）仍由 SAGE 处理，非专家稠密矩阵仍由无状态 Sinkhorn 处理，未来需研究完整的 MoE 参数分类法下的内存高效更新。

## 7. 优点

- **问题定位精准**：不是笼统地报告"直接迁移失败"，而是通过细致的消融实验逐层定位到路由专家、再定位到"时间平滑缺失"这一具体因果机制，诊断逻辑严密。
- **方法设计巧妙**：隐藏动量通过梯度缓冲区生命周期实现，避免了显式存储专家一阶矩张量，在工程层面有实操价值；不必为专家维护额外的 AdamW 状态也能获得大部分收益。
- **诊断与工程分离**：通过 MESH-FULL / MESH-B-FULL 全状态诊断变体，将"算法层面时间平滑的价值"与"工程层面隐藏动量的实现质量"分开度量，方法论严谨。
- **结论表述克制诚实**：作者明确表示 MESH 不优于 AdamW，定位为"内存-质量前沿上更优的点"，并区分了单种子诊断与多种子性能声明，避免了过度声称。
- **实验设计系统**：从专家角色分配到更新成分分解，再到路由模式控制和负面干预，形成了完整的假设-检验闭环。

## 8. 不足与局限

### 8.1 实验覆盖不足

- **架构单一**：仅实验了 110M 参数的 nanowhale MoE 模型，未验证 MESH 在更大规模（如 1B、7B 及以上）MoE 模型上的有效性。
- **数据集单一**：仅使用 FineWeb-Edu 一个数据源，未在多样化的语料（如多语言、代码、混合领域等）上验证。
- **训练步数有限**：5,000 步（约 2.62B tokens）对预训练而言偏短，不足以完全反映长期训练的动态行为。
- **种子覆盖有限**：多种子比较仅两个额外种子，统计功效较弱。
- **评估集偏小**：512 个评估样本不足以在高精度下区分相近的损失差异（0.01–0.02 量级）。

### 8.2 偏差风险

- **超参数偏差**：SAGE/MESH 和 AdamW 使用了不同的学习率和权重衰减等超参数，虽然各有官方配置依据，但无法完全排除"调参不充分导致差距"的嫌疑。
- **隐藏动量实现脆弱性**：依赖 Trainer/Accelerate/DDP 训练循环中的 prepare-before-backward 钩子，在分布式环境或不同训练框架中的泛化性未知；若梯度缓冲在包装模型中被清除，会导致动量丢失。
- **MESH-B 的块统计使用 H 而非原始梯度**：作者自认这是一个简化选择，与最强的 seed-42 诊断一致，但未系统比较不同统计源的影响。

### 8.3 应用限制

- **残余差距**：MESH 和 MESH-B 在评估损失上仍落后 AdamW 约 0.05，不适合对精度要求极高的任务直接替换。
- **词汇表仍占大量状态**：在 nanowhale 中，词汇参数占比极高，MESH 的内存节省主要来自非词汇部分；在词汇表占比不同的模型中，内存优势可能缩小。
- **需要针对 MoE 架构做角色分配**：MESH 不是通用优化器，需要根据参数类别（嵌入、非专家稠密、路由专家、共享专家）进行精细角色分配，部署复杂度高于一体化优化器。
