## 摘要
混合专家（MoE）模型因其在保持高模型容量的同时仅激活每个标记的一小部分参数，从而提升计算效率，因此非常适合边缘部署。然而，边缘端的MoE推理从根本上受到内存的限制。专家参数规模庞大，且由于容量、成本和功耗约束，通常驻留在片外内存中，这使得专家加载成为关键路径上的瓶颈。我们提出了APEX：自适应专家预取，一种预测性资源管理框架，将专家加载与有用计算重叠。APEX引入了一个轻量级预取路由器，在注意力块之前预测候选专家，通过学习到的置信度模型动态获取额外专家。这种自适应策略实现了超过99%的重叠准确率，显著优于固定的top-k预取技术。APEX支持两种执行模式：一种保持正确性模式，保证精确的路由语义；另一种无停顿模式，通过操作可用专家来消除残余停顿，且对应用准确率的影响可忽略不计。在多个MoE模型上，与最先进的基线相比，保持正确性模式将每令牌延迟降低了高达26%，并将能量延迟积（EDP）改善了高达41%，而无停顿模式在准确率影响可忽略的情况下提供了额外的效率提升。这些结果确立了自适应、置信度驱动的专家预取作为边缘系统上高效MoE推理的有效方法。

## Abstract
Mixture-of-Experts (MoE) models are attractive for edge deployment because they provide high model capacity while activating only a small subset of parameters per token, improving compute efficiency. However, MoE inference at the edge is fundamentally limited by memory. Expert parameters are large and often reside in off-chip memory due to capacity, cost, and power constraints, putting expert loading to the critical path. We present APEX: Adaptive Expert Prefetching, a predictive resource management framework that overlaps expert loading with useful computation. APEX introduces a lightweight prefetch router that predicts candidate experts before the attention block to dynamically fetch additional experts using a learned confidence model. This adaptive strategy achieves over 99% overlap accuracy, significantly outperforming fixed top-k prefetching techniques. APEX supports two execution modes: a correctness-preserving mode that guarantees exact routing semantics, and a stall-free mode that eliminates residual stalls by operating on available experts with negligible impact on application accuracy. Across multiple MoE models, the correctness-preserving mode reduces per-token latency by up to 26% and improves energy-delay product (EDP) by up to 41% over state-of-the-art baselines, while the stall-free mode provides additional efficiency gains with negligible impact on application accuracy. These results establish adaptive, confidence-driven expert prefetching as an effective approach for efficient MoE inference on edge systems.

## 1. 论文核心问题与整体含义（研究动机与背景）

- **背景**：MoE（Mixture-of-Experts，混合专家）模型通过每次仅激活少量专家参数，在保持高模型容量的同时显著降低单 token 计算开销，因此非常适合边缘部署。然而，边缘平台的内存容量、功耗和成本受限，全部专家权重无法常驻在片上高带宽内存（如 HBM/GDDR）中，而必须存放在片外低成本的 LPDDR 内存中。
- **核心瓶颈**：专家权重位于片外内存，导致“路由 → 加载专家 → 执行”流水线中专家加载的延迟直接暴露在关键路径上。论文以 Granite-3.1-3B-A800M 模型为例，在代表性边缘加速器上测得专家加载占单 token 推理延迟的 43%，且等待期间计算单元仍消耗静态功耗。
- **现有方法的不足**：已有预取方法（如 ProMoE、Fate、HOBBIT）通常采用固定 top-k 预取策略，预测精度虽高（70–85%），但预测误差会导致部分层反复出现缺页停顿，且无法适应跨层、跨 token 的路由不确定性。平均重叠率高的假象掩盖了最坏情况层的性能损失。
- **APEX 的定位**：论文提出将专家预取视为一个”自适应的每 token 资源管理决策”，通过学习置信度模型动态确定额外预取专家数，使预取开销与覆盖收益达到平衡，将专家加载从关键路径上移除。

## 2. 论文提出的方法论

### 2.1 核心思想

APEX 在每个 MoE 层的注意力块之前放置一个轻量级**预取路由器**，利用注意力前的层表征提前预测当前层最可能被原始路由器选中的专家，并异步发起 DMA 预取，使专家加载与注意力计算重叠。关键在于：**预取的专家数量不是固定的，而是由学习到的置信度模型每 token 动态确定**，即 top-(k + δ̂(x)) 策略。

### 2.2 预取路由器与置信度模型

- **预取路由器**：与原版 MoE 路由器结构相同（线性层 + softmax），置于注意力块之前，通过 KL 散度蒸馏损失（公式 10）从冻结的原版路由器学习专家概率分布，无需修改或重训练基础 LLM。
- **序数 Logistic CDF 模型**：对每个候选额外预算 δ，定义覆盖概率 pδ(x) = Pr(δ ≥ δ*|x)，其中 δ* 为实现全部路由专家被覆盖所需的最小额外预算（oracle delta）。pδ(x) 通过序数 Logistic 形式建模：
  \[
  pδ(x) = σ(θδ − wᵀx)
  \]
  其中 θδ 为有序阈值（θ0 ≤ θ1 ≤ … ≤ θN−k），w 为学习参数。该模型保证概率的单调性，构成合法 CDF。
- **动态决策**：给定覆盖率目标 τ，选择最小的 δ 使得 pδ(x) ≥ τ（公式 9）。高置信度 token 只需较小的 δ，而低置信度 token 自动获得更大的预取预算，实现“按需获取、刚好覆盖”。

### 2.3 两种执行模式

- **正确性保持模式（Correctness-preserving）**：严格遵循原始路由语义。若存在预取遗漏，通过异步补救加载（miss correction），在计算其他已可用专家的同时并⾏获取缺失专家，最终仍使用完整的原始专家集合加权求和。
- **无停顿模式（Stall-free）**：当可容忍近似时，直接用已在预取集合中的最高权重候选专家替换缺失的少量路由专家（算法 1），完全消除残余停顿，换取少量精度损失。

## 6. 论文的主要结论与发现

- 固定 top-k 预取即使在高平均重叠率下仍会出现大量残余停顿（挑战 1），而少量额外预算（top-(k+δ)）即可近乎完全消除漏取（关键洞察）。
- APEX 在 τ=0.90 时实现 **>97% 的逐层重叠率**，在更高阈值下达到 **>99%**，远超 ProMoE（约 82–88%）和静态过度预取策略。
- 正确性保持模式将每 token 延迟降低 **最高 26%**，EDP 改善 **最高 41%**（对比最先进基线）；能量分解显示，APEX 通过减少空闲/漏电能量（57→8 mJ）大幅抵消额外 I/O 传输能耗。

- APEX 开销极小：新增参数占模型权重 0.022%–0.060%，运行时性能开销不超过 0.051%。

## 7. 优点

- **自适应性**：将预取预算从固定的全局超参数转化为每 token 的置信度驱动决策，直击 MoE 路由不确定性随 token 和层高度变化的本质。
- **轻量化设计**：只训练轻量级辅助组件，基础 LLM 保持冻结，无需重训练或修改路由语义。
- **理论支持**：以序数 Logistic CDF 形式保证概率单调性，形式化清晰，决策可解释，支持用户通过单个阈值 τ 在精度/开销之间权衡。
- **两种模式兼顾正确性与效率**：正确性保持模式适合精度敏感场景，Stall-free 模式适合性能优先场景，部署灵活。
- **实验全面**：覆盖从 1B 到 16B 的不同模型规模、多种上下文长度、带宽敏感性和量化精度，评价维度丰富。

## 8. 不足与局限

- **无真实硬件实测**：系统级结论基于 CHIPSIM 协同仿真（已对真实平台校准但非 APEX 加速器本身），缺乏 FPGA 或硅原型验证，论文亦承认这一点。
- **评估场景单一**：仅针对单用户、延迟敏感的 decode 阶段，虽然提及支持批量推理，但未提供批处理场景下并发请求的延迟/吞吐评估。
- **Stall-free 适用性受限**：在低 top-k 模型（如 Phi-7B，k=2）上精度损失显著，该模式的通用性不足，需按模型路由结构谨慎选择。
