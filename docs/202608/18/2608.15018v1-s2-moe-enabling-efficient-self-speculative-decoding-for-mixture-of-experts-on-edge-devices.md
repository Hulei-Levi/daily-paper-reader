## 摘要
由于严苛的内存和带宽限制，在边缘设备上部署大型语言模型（LLM）进行推理颇具挑战。尽管已有研究提出推测解码和混合专家（MoE）来提升推理效率，但简单地将两者结合往往会产生过多的验证开销以及较差的专家复用，从而限制了它们在内存受限的边缘场景中的有效性。在这项工作中，我们提出了S2-MoE，一个用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展来减少冗余验证，通过复用感知的专家门控来提升验证效率，并通过共享上下文来对齐草稿执行与目标执行。S2-MoE已在llama.cpp中实现，在边缘设备上的多种MoE模型和数据集上，相较于标准自回归解码，实现了最高5.3倍（平均约2.0倍）的加速。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

## 2. 论文提出的方法论

S²-MoE 由三个互补组件构成，整体流程为：目标模型先处理提示并建立 KV 缓存，在推测阶段草稿模型基于共享上下文生成候选树，经过路由感知自适应扩展裁剪低效用分支，再通过复用感知专家门控调整验证时的专家激活，最后执行并行验证并回滚临时 KV 更新。

### 2.1 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）
- 目标：在扩充推测树时同时考虑候选 token 的接受概率和验证代价，避免低质量、高开销分支。
- 预期收益：对于草稿 token *i*，其前缀置信度 *pᵢ* = ∏ⱼ₌₁ᵏ *pᵢ,ⱼ*，预期收益定义为 *Bᵢ* = *pᵢ* · *T_AR*（*T_AR* 为一次自回归解码的平均延迟）。
- 边际验证代价：计算加入 token *i* 后新引入的专家集合大小，乘以单个专家的验证延迟 *T_exp*，得到 ΔC_ver(i|S)。总代价 *Cᵢ* = ΔC_ver(i|S) + C_draft_i。
- 效用函数：*Uᵢ* = *Bᵢ* / *Cᵢ*，仅当 *Uᵢ* ≥ 1 时才将该候选加入推测树。这比固定宽度或纯置信度剪枝更适应 MoE 的专家级验证成本差异。
- 实验表明该成本模型与实际验证延迟高度相关（R²=0.943–0.999，MAPE=0.8–4.5%）。

### 2.2 复用感知专家门控（Reuse-aware Expert Gating）
- 目标：提高并行验证时多个草稿 token 之间的专家复用率，降低参数访问量。
- 过程：
  1. 跨 token 专家重要性聚合：对每个 token 按其置信度加权，聚合各专家在该批草稿 token 上的门控 logits，得到全局专家重要性 *gₑ* = Σ_b w_b · ℓ_b,e。
  2. 全局优选专家选择：从 *gₑ* 中选取至多 cap 个专家作为“复用奖励专家”集合 E★（cap ≥ k，以保证原始 top-k 专家仍可被选）。
  3. 软路由偏置：对每个 token 的门控 logits 加上与“top-1 专家与第 k+1 专家分数差”成比例的偏置 λ_b · 1[e ∈ E★]，从而把低置信度 token 的专家选择推向已有的高复用专家，同时尽量保留高置信度 token 的原始路由。
  4. 在 CUDA 中实现融合 kernel，几乎不增加额外开销。

### 2.3 上下文对齐自推测解码（Context-aligned Self-speculative）
- 草稿与目标共享同一个 KV 缓存，避免草稿维护独立上下文导致的误差累积。
- 草稿产生的 KV 更新被视为临时状态，在验证前回滚；只有被接受的 token 才提交到共享缓存中。
- 这样将草稿误差限制在当前推测步内，显著提高长期生成的接受率。

## 6. 论文的主要结论与发现

- S²-MoE 在 Jetson Orin 上实现 1.3×–5.3× 加速，平均约 2.0×；在 RTX 4090 上实现 1.2×–2.9× 加速。
- 相比于专家稀疏自推测（ES）和层稀疏自推测（LS），S²-MoE 显著改善了它们在紧内存下甚至负加速的问题。
- 相比 EAGLE-3，S²-MoE 在不同 MoE 模型上更稳定地取得加速，且无需额外训练。
- 相比 Cascade，S²-MoE 通过对当前 step 的 token 级验证效用估计，避免历史信号滞后，提升一致性。
- 复用感知专家门控带来的模型质量影响很小：任务准确率差异非系统性，长上下文得分与原模型相当，PPL 比率接近 1.0，Top-1 一致率 > 89%。
- 上下文对齐自推测能有效提高接受率（例如 GSM8K 上 OLMoE 提升 79%），是长文本生成的关键。

## 7. 优点

1. **问题洞察深入**：明确将 MoE 推测解码效率分解为输出密度与参数密度的乘积，并识别出专家复用和冗余验证这两个 MoE 特有瓶颈。

4. **软路由偏置保质量**：通过置信度加权聚合和受限软偏置，在提高专家复用率的同时保持高 top-1 一致性，显示出较强的鲁棒性。
5. **实验设置贴近真实边缘场景**：考虑了 16/32/64GB 内存和 SSD/CPU 卸载，且基于 llama.cpp 实现，具备实用参考价值。
6. **提供成本模型校准与质量评估**：不仅报告速度，还验证了验证延迟可预测性和输出分布偏移，增加了可信度。
