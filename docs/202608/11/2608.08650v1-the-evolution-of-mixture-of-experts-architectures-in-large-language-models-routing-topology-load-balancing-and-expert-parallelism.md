## 摘要
混合专家模型在增加参数容量的同时，保持每个令牌激活的计算量有界，但其架构演化无法仅通过按时间顺序发布的模型清单来解释。本技术综述综合了原始论文、官方技术报告和先前综述，沿五个耦合维度组织现代混合专家系统：专家粒度、专家拓扑、路由自由度、负载均衡范围和执行结构。我们将八个架构里程碑描述为一个依赖图，包含六条主线发展和两条正交分支，而非八代相继的生成。然后，我们通过四个控制平面分析各个系统：专家拓扑、路由、均衡和专家并行。这些平面指定了存在哪些专家、哪些专家处理每个令牌、如何控制总负载，以及如何将选定的计算映射到物理设备上。该框架将诸如Top-k路由、共享专家、细粒度专家和动态专家组合等算法选择，与令牌分发、设备放置、全对全通信和通信-计算重叠等系统关注点联系起来。我们以等预算预训练实验、质量和系统指标以及开放研究问题作为结论。主要趋势是从仅仅激活更多稀疏参数，转向解耦语义路由、计算预算和物理执行。

## Abstract
Mixture-of-Experts models increase parameter capacity while keeping the computation activated by each token bounded, but their architectural evolution cannot be explained by a chronological list of model releases alone. This technical survey synthesizes primary papers, official technical reports, and prior surveys to organize modern Mixture-of-Experts systems along five coupled dimensions: expert granularity, expert topology, routing freedom, the scope of load balancing, and execution structure. We describe eight architectural milestones as a dependency graph with six mainline developments and two orthogonal branches, rather than as eight successive generations. We then analyze individual systems through four control planes: Expert Topology, Routing, Balance, and Expert Parallelism. These planes specify which experts exist, which experts process each token, how aggregate load is controlled, and how selected computation is mapped onto physical devices. The framework connects algorithmic choices such as Top-k routing, shared experts, fine-grained experts, and dynamic expert composition with systems concerns including token dispatch, device placement, all-to-all communication, and communication-computation overlap. We conclude with equal-budget pretraining experiments, quality and systems metrics, and open research questions. The main trend is a shift from merely activating more sparse parameters toward decoupling semantic routing, computational budgets, and physical execution.

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架

论文的核心方法论是**"五个维度 + 八个里程碑 + 四个控制平面"**的三层分析体系：

- **五个耦合维度**：专家粒度（expert granularity）、专家拓扑（expert topology）、路由自由度（routing freedom）、负载均衡作用域（scope of load balancing）、执行结构（execution structure）。
- **八个演进节点**：不是八代模型的线性年表，而是由**六个主干节点 + 两个正交分支**构成的依赖图。
- **四个控制平面**：Topology（对象层）、Routing（决策层）、Balance（控制层）、Expert Parallelism（执行层），用于剖析单一 MoE 系统的内部工作机制。

核心观察是：*时间轴（八个节点）与系统剖面（四个控制面）是互补视图，而非两套并列的"发展阶段"。*

### 2.2 统一形式化（Token-choice MoE）

给定第 t 个 token 的隐藏表示 x_t ∈ R^d，Router 计算专家亲和度：

- **亲和度计算**：s_{i,t} = φ(x_t, e_i)，其中 e_i 是专家路由嵌入或 Router 权重
- **Top-k 选择**：K_t = TopK_{i∈{1,…,N}}(s_{i,t})，N 为路由专家数
- **输出**：y_t = x_t + Σ_{i∈K_t} g_{i,t} E_i(x_t)，其中 g 为归一化权重
- **共享专家**：若存在始终开启的共享专家，则额外加上 Σ_j E_shared_j(x_t)
- **系统视角**：K_t 决定了 token 跨越哪些设备、每张卡获得多少 token、每个局部 GEMM 的形状

### 2.3 三目标优化

MoE 不是单目标优化，而是同时追求：

1. **容量（Capacity）**：最大化总参数 P_total
2. **质量（Quality）**：模型表达能力
3. **系统效率（System efficiency）**：控制单 token 激活量 P_active ≈ P_dense + (k/N)P_routed + P_shared

关键张力：**语义上允许 specialization 不均匀，物理执行上又不能出现严重 straggler**。负载变异系数 CV_expert 低有利于 EP 吞吐，但不必然有利于知识专门化。

### 2.4 八个演进里程碑（瓶颈迁移视角）

| 节点 | 名称 | 新增设计变量 | 解决的主导问题 | 转移出的新瓶颈 |
|------|------|------------|--------------|--------------|
| 1 | Dense/Soft MoE（1991, Jacobs et al.） | gating 与专家专门化 | 单模型难以对输入空间分区建模 | 所有专家都计算，容量与 FLOPs 绑定 |
| 2 | 稀疏条件计算（2017, Shazeer et al.） | 稀疏 Top-k 与 capacity | 总参数与单 token FLOPs 解耦 | 离散路由、collapse、token drop |
| 3 | Transformer MoE 与 Expert Parallel（2020-2022, GShard/Switch/ST-MoE） | EP、All-to-All、稳定化 loss | Transformer MoE 的集群级训练 | 通信、straggler、数值与负载稳定性 |
| 4 | 开放权重粗粒度 MoE（2024, Mixtral） | decoder-only 训练与部署闭环 | 证明经典 MoE 可进入开放模型生态 | 大专家知识冗余、组合粒度粗 |
| 5 | Shared + 细粒度专家（2024-2025, DeepSeekMoE/V2、Qwen3） | fine-grained、shared、device limit | 公共知识重复与专家组合不足 | fan-out、小 GEMM、共享路径固定成本 |
| 6 | 超稀疏扩展（2024-2025, PEER、Kimi K2、gpt-oss） | 更大 N、tiny experts、检索路由 | 固定 active budget 下继续扩总容量 | 权重 I/O、检索、低 token/expert |
| 7 | 动态计算（2025, LongCat-Flash） | adaptive compute / zero slots | token 难度不同却使用固定 Top-k | active budget 控制、尾延迟、训练稳定性 |
| 8 | 语义路由与物理解耦（2025-2026, ScMoE、MoHGE、GMoE、Head Parallel） | shortcut、异构/跨层拓扑、结构化通信 | 语义路由被设备拓扑和通信绑定 | 调度复杂度、缓存一致性、大规模验证 |

### 2.5 四个控制平面

- **Topology（对象层）**：定义专家集合 ℰ、知识单元粒度、共享范围和计算异质性。关键演变：少量同构大专家 → Shared/dense + routed → 细粒度专家 → 超稀疏专家 → 异构/动态专家 → 跨层全局/局部 → latent/head 结构化。
- **Routing（决策层）**：逐 token 离散决策，输出 𝒦_t。主流 Router 家族：Noisy Top-k（当前主干）、Top-1 Switch、Balanced assignment（BASE Layers）、Expert-choice、Soft/parameter merging、Bias-controlled Top-k（DeepSeek-V3）、Zero experts/adaptive-k。**Token-choice 成为主流不是因为它优化上最优，而是它最符合自回归在线约束**（当前 token 的路由只依赖当前状态，无需等待未来 token 或求解全局分配）。
- **Balance（控制层）**：观察累积负载 {n_i}，通过 loss、bias、capacity 或 runtime placement 反馈。经典辅助损失 ℒ_bal = (α/N) Σ f_i P_i。演进路径：Sequence/batch 专家均衡 → Device/node/communication-aware 均衡 → 全局 batch ALF bias → 运行时复制与放置。**ALF（Auxiliary-Loss-Free）** 策略增加非梯度路由偏置 b_i，b_i ← b_i + η·sign(n̄ − n_i)，减少均衡目标对模型参数更新方向的直接干扰。论文特别澄清："DeepSeek-V3 完全没有 balance loss"的说法不准确——它使用 batch-wise ALF 作为主机制，同时保留很弱的 sequence-wise auxiliary loss。
- **Expert Parallel（执行层）**：将逻辑专家转化为设备上的 dispatch、局部 GEMM 与 combine。三种通信处理方式：**限制通信拓扑**（device/node-limited routing）、**隐藏通信**（shared computation overlap、DualPipe、ScMoE、token chunking）、**重构通信**（Head Parallel 等确定性通信模式）。论文强调必须区分"总 All-to-All 时间"和"exposed communication time"。

### 2.6 形式化闭环

四个控制平面构成闭环（公式 5）：

```
ℰ = T(θ_topo)                    // Topology: 构造专家集合
𝒦_t = R(x_t, ℰ; θ_route, b)      // Routing: 为 token t 选择专家子集
(b, α, c) ← C({n_i}, π)          // Balance: 依据聚合负载更新 bias/loss/capacity
y_t = EP(x_t, 𝒦_t, π, σ)         // EP: 按 placement π 和 schedule σ 执行
```

存在两类重要的反向依赖：① 物理拓扑约束语义路由（device-limited routing 主动缩小候选集）；② Balance 不只调 Router（runtime replication 可在不改变 𝒦_t 的情况下改善物理负载）。

  - 作为综述，论文的证据来源是 34 篇参考文献（原始论文 + 技术报告 + 综述），覆盖主流开放模型。
- **充分性**：作为一篇框架性综述，论文的分析深度和覆盖面较好；但**缺少一手实验验证**意味着其提出的框架（如"瓶颈迁移"叙事、ScMoE 的有效性判断）本质上仍是**基于文献的定性推断**，尚需后续等预算实验检验。

## 6. 主要结论与发现

1. **核心趋势**：现代 MoE 的竞争焦点已从"稀疏激活更多参数"转向"**解耦语义路由、计算预算和物理执行**"。
2. **架构史本质**：LLM MoE 的架构史不是"专家越来越多"的单线扩张，而是五条路线的共同演化——专家粒度（少而大 → 细粒度 → 超稀疏 → 异构）、拓扑（层内本地 → 共享 → 跨层全局/局部 → latent-head）、路由（简单 Top-k → 全局统计 → bias 控制 → 动态预算

路由（简单 Top-k → 全局统计 → bias 控制 → 动态预算）、负载均衡作用域（sequence/batch 内均衡 → global batch 全局均衡 → runtime replication/placement）、执行结构（串行 EP → shared overlap/DualPipe → 确定性通信模式如 Head Parallel）。这五条路线彼此耦合，任何单点优化都会在其他维度产生新瓶颈，因此"瓶颈迁移"是理解 MoE 演进的最佳透镜。

3. **Token-choice 路由的胜出是系统约束而非语义最优**：尽管 Expert-choice 或全局均衡分配在批量离线场景下能改善负载，但自回归解码要求当前 token 的路由决策仅依赖当前状态，不能等待全局求解或未来 token；因此 token-choice（尤其是带 bias 控制的 Top-k）成为主流，本质上是**在线性约束下最可行的设计方案**，而非语义上最优。

4. **物理执行已成为架构演进的第一公民**：从 GShard 的 EP + All-to-All 起，通信和负载就从未脱离架构设计；DeepSeek/V3 的 device-limited routing、DeepSeek-V3 的 runtime EPLB、ScMoE 的通信重构、Head Parallel 的确定性通信，均表明"语义路由自由"正在让位于"物理可执行性"约束。作者据此提出 "执行结构" 应与 "路由" 并列为一个独立设计维度。

5. **评估必须走向等预算消融**：论文强烈批评跨论文模型能力对比，认为已知训练配置不一致时任何分数比较都无意义；唯一的可靠路径是固定 token 数、数据配比、active 参数和优化器，分别测量 FLOPs-matched 与 wall-clock-matched 结果。此外，系统指标（暴露通信时间、MFU、P99 等）应与质量指标一同报告，否则架构改进无法归因。

6. **未来方向集中于三个未解问题**：一是动态计算（adaptive/zero experts）能否在不破坏训练稳定性的前提下实现真正的按难度分配算力；二是超稀疏（N 极大、active 极小）场景下权重 I/O 与检索是否取代 GEMM 成为新瓶颈；三是语义路由与物理拓扑的彻底解耦（ScMoE、latent/head 结构）能否扩展到数万亿参数规模并保持高效率。

## 7. 局限性与批判性评价

### 7.1 论文自身的局限性

- **无一手实验支撑**：作为框架性综述，作者未进行任何等预算对比实验，其核心叙事（如"ScMoE 有效""ALF 优于辅助 loss"）主要依赖引用文献的间接证据，缺乏可复现的验证。因此该框架属于**假设性理论建构**，而非已验证结论。
- **"瓶颈迁移"叙事存在简化风险**：将 30 年 MoE 历史压缩为八个"里程碑"，可能忽略了某些重要中间工作（如 Switch 之前的路由稳定性技巧、T5-MoE 等）的历史贡献；不同模型之间的界限在真实代码中往往是渐进融合的，而非节点式突变。
- **引用范围有限**：仅 34 篇参考文献，大量重要工作（如 DeepSeek-V2 的 MLA、Mixtral 的 MoE 层位置、Qwen MoE 的细粒度、Switch 的 capacity 分析）虽被提及但未深入展开；对多模态 MoE、MoE-LoRA 等已明确排除，这限制了结论的通用性。
- **系统指标定义不够精确**：论文多次使用 "exposed communication time" 但未给出统一定义或测量协议；"MFU" 也未区分训练与推理场景，实践中不同论文的计算方式差异较大。

### 7.2 作为分析者的综合评价

- **贡献**：论文最大的价值不是提供新实验，而是**重构了 MoE 设计空间**——将分散的架构技巧（shared expert、fine-grained、ALF、EPLB、ScMoE、Head Parallel）统一到 "Topology–Routing–Balance–EP" 四个控制平面之下，并用"瓶颈迁移"串起时间线，使读者能看清单点优化如何触发下游连锁问题。这种系统化视角在现有 MoE 综述中较为少见。
- **立场辨识**：作者明显倾向于"语义-物理解耦"与"执行结构重塑"（如 ScMoE、Head Parallel）是未来主线，对经典 Top-k + 辅助 loss 路径的评价略偏批判；阅读时需注意其选材与权重分配受到自身研究偏好影响。
- **实用性**：Table 7 的等预算消融矩阵可直接作为研究组设计 MoE 预训练实验的 checklist，系统侧指标清单也为工程团队提供了重要的报备规范；这些建议优于单纯罗列模型分数的做法。

## 8. 结论

该论文以"瓶颈迁移"为核心叙事，将 LLM MoE 的架构演进重构为五个耦合维度上的共同演化，提出四个控制平面组成的闭环分析框架，并给出了面向未来的等预算消融实验设计建议。其核心主张——**MoE 的演进正从"如何稀疏激活更多参数"转向"如何在语义、计算与物理执行之间解耦"**——具有较强解释力，但尚需一手实验验证。作为一篇技术综述，它的结构性贡献大于实证贡献，适合作为研究者进入 MoE 设计空间的地图，而非判断具体模型优劣的裁判。
