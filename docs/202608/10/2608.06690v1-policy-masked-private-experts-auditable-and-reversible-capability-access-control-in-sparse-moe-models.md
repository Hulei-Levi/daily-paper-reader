## 摘要
大多数语言模型的访问控制调节行为，同时让每个请求可以访问相同的计算。我们研究一个不同的系统问题：可信授权能否决定前向传播可以访问哪些新训练的参数？策略掩蔽的私有专家冻结预训练的稀疏混合专家（MoE）模型，训练一个不相交的专家分支，并在top-k路由之前选择公共或私有池。由此产生的声明是狭窄但可测试的：在声明的可信计算基（TCB）下，未授权的请求不执行任何私有专家。这并不意味着公共模型缺乏相同的语义能力。我们在Qwen3-30B-A3B和DeepSeek-V2-Lite上测试了执行控制与任务效用之间的这种分离。三个Qwen BF16种子更新了所有32个私有专家，而公共指纹保持不变。在64个对抗性场景和96个拒绝/失败关闭事件中，未授权的私有执行为零；独立的钩子完全匹配11,616个路由的私有行，允许-拒绝-允许恢复是精确的。在两个前瞻性冻结的Qwen基准上，私有分支将精确工具使用提高了5.0个百分点（pp）（五个对零个不一致；单侧Holm p = 0.03125，相应的双侧精确p = 0.0625）和21.3 pp（百分位自举95% CI [13.3, 29.3]，Holm p = 0.000031）。三个盲态模型评估者保留了18.7 pp的正外部效应（95% CI [9.3, 28.0]）。参数匹配的LoRA具有相似的外部效用，但事后请求门在拒绝条件下留下了1,225次适配器调用；而不相交的专家分支没有留下任何调用。DeepSeek复现了路由不变性并获得27.0 pp的提升。有效的密封评估是接近中性的。这些结果支持对已训练参数路径进行可审计、可逆的控制，同时表明有用的迁移仍然依赖于分布。

## Abstract
Most language-model access controls regulate behavior while leaving the same computation available to every request. We study a different systems question: can trusted authorization determine which newly trained parameters are reachable by the forward pass? Policy-Masked Private Experts freezes a pretrained sparse Mixture-of-Experts (MoE) model, trains a disjoint expert branch, and selects the public or private pool before top-k routing. The resulting claim is narrow but testable: under the declared trusted computing base (TCB), an unauthorized request executes no private expert. It does not imply that the public model lacks the same semantic capability.   We test this separation between execution control and task utility in Qwen3-30B-A3B and DeepSeek-V2-Lite. Three Qwen BF16 seeds update all 32 private experts while the public fingerprint remains unchanged. Across 64 adversarial scenarios and 96 deny/fail-closed events, unauthorized private execution is zero; independent hooks exactly match 11,616 routed private rows and allow-deny-allow recovery is exact. On two prospectively frozen Qwen benchmarks, the private branch improves exact tool use by 5.0 percentage points (pp) (five versus zero discordances; one-sided Holm p = 0.03125, corresponding two-sided exact p = 0.0625) and 21.3 pp (percentile-bootstrap 95% CI [13.3, 29.3], Holm p = 0.000031). Three arm-blinded model evaluators retain a positive external effect of 18.7 pp (95% CI [9.3, 28.0]). A parameter-matched Lora has similar external utility, but a post-hoc request gate leaves 1,225 adapter calls under deny; the disjoint expert branch leaves none. DeepSeek reproduces the route invariant and gains 27.0 pp. A valid sealed evaluation is near-neutral. These results support auditable, reversible control over a trained parameter path, while showing that useful transfer remains distribution dependent.

## 1. 论文的核心问题与整体含义

- **背景**：现有的大语言模型（LLM）访问控制通常只调节模型“行为”——例如通过系统提示词、RLHF/DPO 后训练、输出过滤器等手段让模型在不同用户面前表现不同。但这些方法无法回答一个底层系统问题：**未授权请求是否在物理计算层面触达了被限制的参数路径？**
- **核心问题**：能否让可信授权机制（而非提示词）直接决定前向传播（forward pass）中哪些新训练的参数可被触及？换言之，将“能力访问控制”从行为层面下沉到**参数可达性（reachability）层面**。
- **总体思路**：论文提出 **Policy-Masked Private Experts（策略掩蔽的私有专家）** 机制：冻结预训练稀疏 MoE 模型，额外训练一个不相交的私有专家分支，在 top-k 路由之前通过可信授权元数据选择公共池或私有池。未授权请求在硬掩码层面无法进入任何私有专家。
- **关键澄清**：该机制只保证“私有模块不执行”，**不声称**公共模型不具备相同语义能力，也不声称私有分支一定能带来能力提升。这是一个刻意的、狭窄的声明边界。

## 2. 方法论

### 2.1 核心思想与架构

- 在选定的预训练 MoE 层中，复制专家架构创建**不相交的私有专家池**。
- 公共专家及所有非私有参数**完全冻结**。
- 在 top-k 路由执行前，通过可信授权元数据解析出布尔值 τ ∈ {0, 1}，生成策略掩码：

```
m_{ℓ,e}(τ) =
  0,      τ=1, e ∈ 私有池
  0,      τ=0, e ∈ 公共池
  -∞,     其他情况
```

- top-k 选择仅在应用掩码后的 logits 上进行：`z_ℓ(h) + m_ℓ(τ)`。
- **allow** 时只在私有池内路由；**deny** 时只在原始公共池内路由；两池互斥。
- **提示词文本不能改变 τ**；缺失、畸形或非布尔型的授权元数据一律失败关闭（fail-closed）为 deny。

### 2.2 训练与检查点

- 仅私有门控与专家权重需要梯度，公共模型指纹训练前后校验不变。
- 使用标准自回归损失、确定性批次规划、最终步检查点选择。
- 要求所有私有专家都收到路由事件并得到非零有限梯度。
- 检查点包含私有权重、优化器状态、源/配置哈希、冻结基座指纹。

### 2.3 三个非等价声明（核心理论框架）

| 声明 | 含义 | 验证方式 |
|------|------|----------|
| **G1: 模块非参与** | τ=0 ⇒ 执行路径与私有专家交集为空 | 路由日志而非生成文本 |
| **G2: 训练隔离** | 公共参数完全不在优化器参数集中，更新为零 | 指纹与优化器审计 |
| **G3: 经验能力分离** | 私有分支在声明分布上带来正向效用提升 | 冻结基准评估；可能失败 |

### 2.4 因果切换协议

固定序列：`public → allow → deny → recovery`，验证：(i) allow/recovery 仅执行私有专家；(ii) deny 零私有执行；(iii) recovery 精确复现 allow。

### 2.5 威胁模型

- 攻击者控制请求文本、可跨请求自适应提示、可模仿特权角色、可利用缺失/畸形元数据、混合策略批次或过期 KV 缓存。
- 攻击者**不能**修改可信策略对象、模型权重、推理二进制或宿主。
- TCB 包含：身份/策略服务、策略到掩码编译、路由实现、签名清单、缓存分离、审计工具。

## 6. 主要结论与发现

1. **G1（模块非参与）被强有力验证**：两个模型上所有 deny/fail-closed 事件中私有专家执行次数为零，允许-拒绝-允许恢复精确，独立钩子与路由日志完全一致。
2. **G2（训练隔离）被强审计**：三个 Qwen 种子和 DeepSeek 均确认公共指纹不变、32/32 专家收到路由与梯度。
3. **G3（能力效用）因基准而异**：
   - Qwen 任务对齐 +5.0 pp（p=0.03125，证据方向有限）。
   - Qwen 外部 +21.3 pp（95% CI [13.3, 29.3]，p=0.000031）。
   - CCTU 密封近中性（RD=-0.00625，p=0.77344），不支持正向假设。
   - DeepSeek 任务对齐 +27.0 pp（p=7.45×10⁻⁹），支持跨模型迁移。
4. **LoRA 与私有专家的关键区别**：参数匹配的 LoRA 逻辑门控虽可精确恢复，但 deny 条件下仍有 **1,225 次物理适配器调用**，无法达到零执行边界。私有专家分支因在路由前整体移除，具备更干净的审计面。
5. **行为等同性不是安全终点**：deny 与 public 输出在某些情况下字节一致、在另一些批处理中不一致，但无论是否一致都不影响 G1 的成立。

## 7. 优点

- **问题定义清晰**：将“能力访问控制”正式化为三个非等价声明（G1/G2/G3），避免混淆安全机制与任务效用。
- **机制简洁且可审计**：在 top-k 路由前加硬掩码，架构改动极小，却将安全边界从行为层面下沉到物理执行层面，可审计性极强。
- **实验严谨性高**：预注册、前瞻冻结、密封基准、独立钩子验证、失败日志记录、哈希链复现，整体遵循“思考→承诺→运行→记录”的科学纪律。
- **对照设计周到**：六个条件矩阵隔离了训练、掩码、提示词、适配器等变量的贡献；参数匹配 LoRA 提供了极具说服力的反事实对比。
- **坦率披露边界**：近中性密封结果、模型（而非人类）评估者的局限、分布依赖的迁移效应均如实报告，未过度宣称。

## 8. 不足与局限

- **架构覆盖有限**：仅在两个稀疏 MoE 模型、每模型仅两层的工具调用域中验证，不适用于稠密模型、多私有层级、持续学习或分布式服务场景。
- **能力边界**：共享注意力、残差流和冻结公共路径仍可能独立实现相似行为，因此 deny 不能证明公共模型缺乏相应能力。
- **端到端安全风险**：TCB 庞大（身份服务、掩码编译器、缓存管理器、内核等）；定时/内存/路由计数旁路信道未分析。
- **审计日志本身的隐私风险**：精确路由痕迹可能泄露敏感策略元数据，需要额外的访问控制和保留限制。
- **统计功效有限**：外部基准仅 75 例工具必需样本；盲态评估者为模型而非人类；DeepSeek 仅一个任务套件。
- **公平性担忧**：分层访问模型可能固化不公平或不可透明化的限制，部署需合法授权基础、申诉路径和最小特权默认。
- **CCTU 密封结果为中性**：这一“干净的空结果”恰恰提示私有分支的能力迁移高度依赖数据分布，不能做泛化宣称。
