## 摘要
程序性视频语言模型必须从相同的视觉证据中解决异构任务，包括动作识别、预测和程序预测。密集Transformer解码器在各任务间共享相同的前馈网络，这可能会纠缠任务行为，并使受控能力扩展变得困难。稀疏专家混合（MoE）解码器提供条件计算，但token级学习路由与任务级程序目标并不自然对齐。我们提出MoTE（任务专家混合），一种解码器架构，将大语言模型的前馈网络转换为任务特定的专家，同时保持多模态骨干共享。每个示例遵循一条样本级任务路由，因此活动任务专家计算与存储的任务专家数量保持独立。我们将该设计实例化为VideoLLM-MoTE，并使用显式任务路由在五个COIN基准上进行评估。五专家模型每个样本激活约2B LLM参数，并实现比近期VideoLLM基线更高的平均top-1准确率。在相同专家拓扑下，它优于密集的全专家激活和学习到的稀疏路由控制。这些结果表明，任务结构化路由为多任务视频语言学习提供了一种可解释且计算高效的解码器替代方案。

## Abstract
Procedural video-language models must solve heterogeneous tasks from the same visual evidence, including action recognition, forecasting, and procedure prediction. Dense transformer decoders share the same feed-forward networks across tasks, which can entangle task behavior and make controlled capability expansion difficult. Sparse Mixture-of-Experts (MoE) decoders provide conditional computation, but token-level learned routing is not naturally aligned with task-level procedural objectives. We propose MoTE (Mixture of Task Experts), a decoder architecture that converts large language model feed-forward networks into task-specific experts while keeping the multimodal backbone shared. Each example follows one sample-level task route, so active task-expert computation remains independent of the number of stored task experts. We instantiate this design as VideoLLM-MoTE and evaluate it on five COIN benchmarks using explicit task routes. The five-expert model activates ~2B LLM parameters per sample and achieves higher average top-1 accuracy than recent VideoLLM baselines. Under the same expert topology, it improves over dense all-expert activation and learned sparse-routing controls. These results show that task-structured routing provides an interpretable and compute-efficient decoder alternative for multi-task video-language learning.

## 1. 核心问题与整体含义

- 论文关注**程序性视频（procedural video）中的多任务视频语言理解**。模型需要从同一段视觉证据中同时解决多个异构任务，如当前步骤识别、下一步预测、动作/任务识别、程序序列预测等。
- 现有密集 Transformer 解码器在所有任务间**共享同一套前馈网络（FFN）**，导致不同任务的行为相互纠缠，且难以受控地扩展新能力。
- 稀疏 MoE 虽然能提供条件计算，但传统方法通常做 **token/图块级别的学习路由**，与**任务级别的程序性目标**并不对齐，路由缺乏可解释性和任务语义。
- 论文提出 **MoTE（Mixture of Task Experts）**：把大语言模型中的共享 FFN 转换为**任务专用专家**，同时保留共享的视觉-语言骨干和注意力路径。
- 核心设计思想是**每个样本走一条任务级路由**，只激活与该任务对应的专家，因此**激活参数数量与存储的专家数量解耦**——可以存储很多专家，但每样本只需要计算其中一条路径。
- 论文将 MoTE 实例化为 **VideoLLM-MoTE**，在 5 个 COIN 视频理解任务上验证，仅激活约 2B LLM 参数即可超越多个更大的 VideoLLM 基线；同时验证了跨领域（文档理解）和跨数据集扩展能力。

## 2. 方法论

### 2.1 整体架构

- 输入为 `(v, x, t, y)`：视频片段/帧序列 `v`、自然语言提示 `x`、任务身份 `t`、目标回答 `y`。
- 组件包含：
  - **视觉编码器**（SigLIP 2 ViT-L/16-384）：提取帧特征，每帧用 1 个 CLS token + 3×3 池化网格，共 10 个视觉 token。
  - **可训练两层 MLP 投影器**：将视觉 token 映射到 LLM 隐藏维度。
  - **LLM 解码器**（Llama-3.2-1B-Instruct），其 FFN 被替换为 MoTE 专家模块；采用 LoRA 进行微调。
- 视频帧、prompt token 和视觉 token 在送入解码器前按模板拼接；注意力路径、语言模型 embedding、视觉编码器是共享的。

### 2.2 MoTE 解码器模块

- 对于每一层 `l`，将原始密集 FFN `F_l` 替换为：
  - 一组任务专家 `{F_l^1, ..., F_l^M}`；
  - 一个**始终激活**的共享专家 `F_l^sh`。
- 计算流程：
  - 先经过共享的 Grouped-Query Attention（GQA）：
    `H̃_l = H_l + GQA_l(LN(H_l))`
  - 然后按任务路由 `r` 激活对应的任务专家，并与共享专家一起加回残差流：
    `H_{l+1} = H̃_l + λ_sh F_l^sh(LN(H̃_l)) + λ_task F_l^r(LN(H̃_l))`
- **初始化策略**：共享专家和任务专家都从预训练密集 FFN 拷贝初始化（类似 Sparse Upcycling），避免从随机变换开始，使共享与任务路径能在训练中分化。

### 2.3 任务路由选择

- **训练阶段**：直接使用任务标签 `t` 作为路由，即 `r = t`。每个样本只激活对应的任务专家和共享专家，更新它们的参数；其他专家不参与计算。
- **推理阶段**（无显式任务 id 时）：
  - 每个专家预先注册一段自然语言描述 `d_m`；
  - 用冻结文本编码器（MiniLM-L6-v2）计算 prompt 与专家描述的归一化余弦相似度；
  - 取最高相似度对应的专家作为路由：
    `r_prompt(x) = argmax_m φ̄(x)ᵀ φ̄(d_m)`
  - 与固定维度的学习 gate 不同，该描述注册表支持在训练后添加/删除专家描述，无需改动解码器参数。

### 2.4 训练目标

- 采用 VideoLLM-online 风格的双目标：
  - **LM Loss**：对受监督的回答 token 计算标准自回归交叉熵；
  - **Stream Loss**：对不需要回答的帧位置预测 EOS，使模型保持静默。
- 对 COIN 离线任务，流式静默监督被关闭，损失退化为标准路由语言建模：
  `L_COIN = -1/N Σ l_{j+1} log pθ(a_{j+1} | H≤j, r)`

### 2.5 模块化任务专家适配

- **专家添加**：新增任务时插入新 FFN 专家（从密集 FFN 或共享专家初始化），冻结原有所有模块，仅训练新增专家，从而避免遗忘旧任务。
- **专家移除**：可直接删除对应层的专家并从描述注册表移除其描述，实现任务能力的“卸载”，这在密集解码器中很难实现。

## 6. 主要结论与发现

- **任务身份是有用的结构化信号**：在同一专家拓扑下，显式任务路由的 COIN 平均精度最高（62.9%），优于全专家密集激活（61.5%）和 token 级学习路由（61.4%），也优于样本级学习路由（62.1%）。
- 性能优势主要集中在**程序级/长时预测任务**（Proc.+ 提升 +2.7 个百分点），说明任务路由在任务边界与计算需求真正对齐时收益最大。
- **MoTE 能够以小搏大**：只用 1B 基础模型 + 2B 激活参数，就超过了需要激活 8B 参数的视频语言基线，同时降低 TFLOPs 和延迟，提高解码吞吐。
- **模块化扩展可行**：顺序添加专家时，旧任务精度完全保持，说明任务 FFN 专家是相对独立的功能模块；但冻结旧专家的扩展在峰值精度上不如联合训练（61.0% vs 62.9%），体现稳定性-可塑性权衡。
- **跨数据集、跨域迁移有效**：
  - 单一模型从 Ego4D 叙事扩展 COIN 五任务，仍保持在线叙事能力（Fluency 最高）；
  - 将 GLM-OCR 转为 MoTE 后，新增 KIE 路由在 SROIE/CORD 上大幅提升（CORD 20.07%→95.79%），且原始 OCR 路由在 OmniDocBench 上完全不变。
- **共享/任务分离**：共享注意力与共享专家处理通用表示，FFN 专家负责任务特定转换，这种解耦值得推广。

## 7. 优点

- **思路清晰，设计简洁**：把“任务”作为显式路由变量，避免复杂学习门控，可解释性强。
- **计算效率高**：激活参数与专家数量解耦，模型可以按任务数扩展存储容量，但单样本成本恒定。
- **模块化能力强**：专家添加/移除机制清晰，可用于持续学习或合规性“卸载能力”，这是密集模型难以实现的。
- **实验设计周到**：不仅有主结果，还有效率分析、路由粒度消融、专家构建消融、模块化扩展测试、跨域验证、专家交换诊断，能较好支撑“任务专家是模块化单元”的核心主张。
- **跨域验证增强了普适性**：在视频和文档两个模态都验证，说明方法不局限于视频，具有推广潜力。

### 8.2 路由与专家设计局限

- **任务标签在训练时是硬分派（hard assignment）**：每个样本只能路由到一个专家。对真实世界中天然交叠的任务（如“当前步骤识别”与“下一步预测”）而言，硬分派可能丢失任务间的共享信息。论文也未尝试软路由、多任务路由或层级路由作为备选方案。
- **推理时无任务标签时采用 prompt–描述相似度路由**：这实际上是隐式假设“用户 prompt 能清晰对应某个专家描述”。对于未注册的新任务描述、多义 prompt（如“接下来会发生什么？”可能同时对应 Next 与 Proc.+）或组合型指令，该路由逻辑可能产生不稳定行为。论文对该问题的测试仅停留在 5 个简单意图的模板变体上。
- **专家间不存在显式通信**：同一层中只有共享专家与单个任务专家被激活，不同任务专家在训练中完全不对齐，可能导致不同任务在表征空间发生不必要的漂移。论文没有分析专家输出分布的相似性或任务间表征对齐程度。
- **专家描述路由的判别力有限**：MiniLM-L6-v2 是通用句嵌入模型，不是为任务路由优化的。论文未将 prompt 路由与可训练的轻量路由（如线性分类器、小型 MLP）在真实 COIN 推理条件上做对比，只报告了理想化测试的 F1。
- **没有探索 MoTE 与 token 级路由的组合**：作者否定了 token 级学习路由，但并未尝试“任务级硬路由 + 专家内部 token 级软路由”的混合机制，也未讨论在更长输入（如长视频流）下任务路由是否需要帧级自适应。

### 8.3 训练与扩展策略局限

- **训练流程是串行式持续学习的简化版本**：添加专家时冻结所有旧参数只训练新专家，虽然避免了遗忘，但作者自己也承认联合训练所有专家（62.9%）优于纯增量扩展（61.0%）。在需要持续适应大量任务时，这一差距可能进一步扩大；论文未给出更复杂增量训练策略（如小部分旧数据重放、LoRA 解冻、层选择性更新）的对照。
- **专家规模固定**：所有任务专家共享相同 FFN 隐藏维度。但不同任务复杂度差异巨大——例如“任务识别”可能只需简单分类，而“程序序列预测”需要更复杂的推理。论文没有尝试自适应专家容量（如不同层不同 rank 或不同 FFN 大小）。
- **共享专家与任务专家的平衡权重 λ_sh、λ_task 固定为常数**：没有实验展示不同 λ 设置对任务分离质量或性能的影响，也没有验证最优 λ 是否随任务和层变化。
- **跨数据集扩展实验（Ego4D → COIN）只验证了在单一骨干上增加新任务专家**，没有验证多个并行 MoTE 模型之间互相拆装、合并专家（如把模型 A 的厨师任务专家与模型 B 的维修任务专家合并）的可行性。
- **未讨论训练稳定性**：MoE 训练中常见的路由崩溃、专家退化、负载不均衡等问题，在 MoTE 中因任务标签路由天然规避，但作者没有对此做显式分析（如专家输出 norm 变化、梯度冲突测量）。

### 8.4 评估与比较方法局限

- **效率比较不完全公平**：论文将 MoTE 与 VideoLLM-online-8B 等进行 TFLOPs/延迟对比，但后者是密集 8B 模型且预训练数据不同。MoTE 的“2B 激活 + 大量存储专家”在内存占用上其实很高（需要存储所有专家权重），论文没有提供总参数量、显存占用曲线的对比，仅强调激活参数。
- **COIN 任务粒度单一**：所有任务都是片段级/程序级精度评估，没有任务间联动评估（如“下一步预测错误是否导致程序预测错误”的级联误差分析）。
- **Ego4D 在线评估只报告整体 PPL/TimeDiff/Fluency**，没有区分不同动作类别（如长尾动作、物体交互 vs 纯运动动作）的叙事质量。
- **跨域 GLM-OCR-MoTE 实验只验证了 KIE 任务与 OCR 任务的共存**，没有验证多个语言任务（如摘要、问答、翻译）在 MoTE 下的相互影响。
- **补充材料中的 expert-swap 诊断**虽然证明“不同专家功能不同”，但测试范围较小，没有量化替换后性能下降与任务相似度之间的关系。

## 9. 潜在改进方向

- **混合路由机制**：在任务级路由之上叠加 token 级路由或注意力加权，让模型对“任务内部”的非均匀计算需求也能自适应。
- **动态描述注册**：将专家描述由人工预定义改为训练后自动生成（例如用模型分析训练数据后生成自然语言意图向量），减少人工设计描述的成本。
- **多任务共享专家池**：允许多个任务共享一组专家，并通过任务相似度（而非硬编码）动态构造路由，从而在任务数多于专家数时仍能保持表达能力。
- **任务感知的损失加权**：对不同任务设计不同损失权重，避免低难度任务主导共享专家训练。
- **扩展到更大骨干并验证 scaling law**：在 3B/7B 解码器上重复 MoTE 实验，确认 1B 上的结论在大规模下仍成立。
- **长视频在线流式设定**：将 MoTE 与流式缓存机制结合，让任务路由可以随视频内容动态切换（如同一视频先后出现多种任务需求）。

## 10. 总体评价

MoTE 是一篇思路简练、实现清晰、实验安排扎实的工作，其核心贡献在于把“任务”重新引入为模型架构中的一阶路由变量——而不是像大多数 MoE 工作那样在 token 级别做隐式路由。这带来了三方面的收益：

1. **可解释的模块化**：每个任务对应独立的 FFN 专家，训练后可以自由添加、删除、检测其功能；
2. **计算效率不减**：专家总数增加不增加单样本计算成本，模型容量扩展只需存储；
3. **任务间干扰可控**：共享注意力 + 共享专家处理通用信息，任务专家专注任务特定差异。

不过，论文的“以小博大”结论主要建立在 1B 骨干、COIN 数据集和相对简单的提示路由测试上，其宣称的通用性还需更大规模、更长视频、更真实复杂 prompt 的进一步验证。整体而言，这是一篇有启发性的工作，尤其适用于程序性视频理解、多任务学习的模块化部署及持续学习场景，其研究价值在于提出了“任务专家”这一简洁而实用的组织原则，而非在 VideoLLM 基线上刷高精度。
