## 摘要
多模态持续指令微调（MCIT）使多模态大语言模型能够按顺序获取新任务，同时保留先前学习的能力。许多近期方法维护任务特定的LoRA专家，并在推理时将每个输入路由到一个或多个专家。然而，专家路由背后的任务识别问题仍未得到充分探索。我们表明，在广泛使用的MCIT基准上，路由已接近饱和。泄露任务身份的文本指纹以及仅有少量竞争专家的短4-10任务序列，共同掩盖了长时程路由问题。为揭示这一挑战，我们引入了FLEX（指纹减弱的长时程专家检验），一个具有减弱文本指纹的34任务长时程MCIT基准。FLEX将指令和答案格式相似但视觉与知识领域多样的任务分组，规范化其外部模板，并在更大的专家池上评估路由。关键在于，我们将渐进式LoRA路由形式化为软任务即类别的多模态类增量学习（MCIL）：每个任务定义了一个增量路由类别，其完整得分分布提供LoRA混合权重，而硬路由是离散特例。FLEX暴露了这一扩展的任务识别挑战，而MCIL公式为将CIL方法迁移到专家路由提供了原则性接口。我们实例化了PureLoRA作为受控基线，并将四种CIL方法适配到四种MCIT框架，无需修改其LoRA专家或生成流程。我们的即插即用路由器将严格LoRA匹配提升了最高16.3个百分点，整体MacroScore提升了最高4.6点。代码见：https://github.com/RINC-CL/FLEX

## Abstract
Multimodal Continual Instruction Tuning (MCIT) enables multimodal large language models to acquire new tasks sequentially while retaining previously learned capabilities. Many recent methods maintain task-specific LoRA experts and route each input to one or more experts at inference. Yet the task-identification problem underlying expert routing remains under-explored. We show that routing is nearly saturated on widely used MCIT benchmarks. Textual fingerprints that leak task identity and short 4--10-task sequences with few competing experts jointly obscure the long-horizon routing problem. To expose this challenge, we introduce FLEX (Fingerprint-reduced Long-horizon Expert eXamination), a 34-task long-horizon MCIT benchmark with weakened textual fingerprints. FLEX groups tasks with similar instruction and answer formats but diverse visual and knowledge domains, normalizes their outer templates, and evaluates routing over a substantially larger expert pool. Crucially, we formulate progressive-LoRA routing as soft task-as-class Multimodal Class-Incremental Learning (MCIL): each task defines an incremental routing class, whose complete score distribution supplies the LoRA mixture weights, with hard routing as a discrete special case. FLEX exposes this expanding task-identification challenge, while the MCIL formulation provides a principled interface for transferring CIL methods to expert routing. We instantiate PureLoRA as a controlled baseline and adapt four CIL methods to four MCIT frameworks without modifying their LoRA experts or generation pipelines. Our plug-in routers improve strict LoRA matching by up to 16.3 percentage points and overall MacroScore by up to 4.6 points. Code is available at: https://github.com/RINC-CL/FLEX

## 一、核心问题与研究动机

- **问题背景**：多模态持续指令微调（MCIT）旨在让多模态大语言模型（MLLM）顺序学习新任务的同时不遗忘旧任务。近年主流方法维护任务特定的 LoRA 专家（progressive-LoRA pool），在推理时先估计各历史专家上的权重，再进行混合与生成。然而，**专家路由中的任务识别（task identification）难题被长期忽视**。
- **关键观察（路由饱和）**：作者发现现有基准（CoIN、UCIT、TriGap 等）上路由已接近饱和——SAME 在 UCIT 上达到 99.76% 的总体任务-LoRA 匹配率，在 TriGap 上达 96.07%；DISCO 在 24 个任务中的 17 个上超过 80% 匹配。这意味着"任务无关推理"在实践中几乎等效于"任务可知的专家选择"，路由机制本身并未被充分检验。
- **根因分析**：作者将饱和归因于两个相互作用的基准属性：
  1. **文本指纹泄漏（textual fingerprints）**：任务的指令模板、界面字段、格式等表面模式直接泄露数据集身份，模型无需理解图像即可识别任务。例如独特的"Reference OCR token:"字段或分类输出接口。
  2. **短任务序列**：现有基准仅含 4–10 个任务，竞争专家池太小，任务识别过于简单。

## 二、方法论

### 1. FLEX 基准构建
- **FLEX**（Fingerprint-reduced Long-horizon Expert eXamination）：一个 34 任务的长时程 MCIT 基准，旨在弱化文本指纹并扩大专家池。具体做法：
  - 将任务分为 4 类共享格式：5 个 ImageNet-200 分类任务、2 个图文生成（captioning）、7 个多项选择、20 个短答案 VQA。
  - 在每个格式组内实现"至少两个可混淆数据集"共存的构造思路，并规范化共享的外部模板，但保留必要内容（如选项布局、领域特有字段）。
  - 图像域涵盖自然图像、科学图表、医学影像、文档、图表、交通、化学、艺术等多元领域。
  - 数据规模：总计 388,856 训练样本和 85,037 测试样本；每个数据集保留其原生评价指标。

### 2. 任务即类别的 MCIL 公式化（Task-as-Class MCIL）
- **核心思想**：将渐进式 LoRA 路由重新定义为**软任务即类别的多模态类增量学习**问题。在渐进式专家池中，每个任务 k 对应唯一的 LoRA k，于是每个输入样本以任务 ID 为路由标签，构成类增量分类问题：类别数随任务数增长而扩展。
- **关键公式**：
  - 训练阶段将任务标签赋给所有样本：D̃ₖ = {(xₖᵢ, cₖᵢ)}，cₖᵢ = k。
  - 推理时，路由器输出任务分数向量 sₜ(x) ∈ ℝᵗ。
  - **硬路由**：bĉₜ(x) = argmaxₖ sₜ,ₖ(x)，对应离散 One-hot LoRA 选择。
  - **软路由**：αₜ,ₖ(x) = exp(τ sₜ,ₖ(x)) / Σⱼ exp(τ sₜ,ⱼ(x))，对应完整的 LoRA 混合权重。
  - 现有方法（如 DISCO、HiDe-LLaVA）的 CLIP 原型余弦相似度路由恰好等价于**冻结特征上的最近类均值（NCM）分类器**，只是 MCIL 的一种简单特例。

### 3. PureLoRA 受控基线
- 仅包含三个组件：独立训练的任务 LoRA 专家、冻结 CLIP 多模态原型路由器、软 LoRA 组合。
- 融合公式：sₖ(x) = ½sim(fᵥ(v), μᵥₖ) + ½sim(f_q(q), μ_qₖ)，softmax 温度 τ=28。
- 作用：隔离路由效果，将专家训练与路由算法解耦，所有路由增强变体共享相同专家与生成流程。

### 4. 四种 CIL 方法作为即插即用路由器
- **HC**（层次聚类）：每个任务设 100 个分层聚类原型，按最大余弦相似度打分。
- **HC-SOINN**（自适应原型图）：在线自组织网络动态更新原型节点，基于节点距离和局部密度打分。
- **RanPAC**（随机投影+岭回归）：固定随机投影到 1024 维 + ReLU，闭式岭回归分类器输出任务 logits。
- **DDAS**（自编码器重构误差）：拼接 CLIP 双编码器输出，为每个任务训练轻量自编码器，以负重构误差作为任务分数。
- 所有路由器替换仅作用于第一阶段任务评分，**不修改 LoRA 专家、不修改生成管线**，且 CLIP 编码器全程冻结。

  - SAME 本身是固定专家池方法，作者论证其在 FLEX 上存在任务-专家对齐后仍适用任务索引化的指标，但这属于有限的适用条件。

## 六、主要结论与发现

1. **路由饱和确实存在且由文本指纹和短序列共同驱动**。FLEX 上所有框架的 G、R 均显著下降（G 在 9/9 对比中全部下降，R 在 8/9 中下降）；注入任务特定后缀指纹后，路由匹配率快速恢复至接近上限（如 DISCO 从 63.95% 升至 86.36%），证明文本指纹是饱和的主要因素。

2. **CIL 路由器迁移有效**：
   - 在路由敏感的框架（DISCO、SAME、PureLoRA）上，12/12 个 CIL 迁移场景同时提升 M 和 G，10/12 提升严格匹配 R。
   - 最优增益：DISCO+DDAS 提升 MacroScore +4.61；SAME+RanPAC +4.05；PureLoRA+RanPAC +1.54。严格匹配最高提升 16.3 个百分点。
   - Oracle 差距恢复率：DISCO 47.6%、SAME 50.2%、HiDe 29.2%、PureLoRA 28.3%。

3. **路由质量与下游性能的正向关系主要由 Top-1 识别提升驱动**。∆M 与 ∆R 的 Spearman ρ=0.709（p=0.002）显著相关，而 ∆M 与 ∆G 的 ρ=0.215（p=0.425）不显著，说明提高正确专家权重不一定带来下游改善，专家间兼容性才是关键中介。

4. **HiDe-LLaVA 对路由不敏感**：其共享的 remain 层融合将除顶层外所有层的历史专家均值混合，即使顶层匹配率大幅提高，下游 MacroScore 也几乎不变（变化仅 0.26 点），说明架构设计限制了路由改进的杠杆作用。

5. **软路由优于硬路由**：保持相同的 Top-1 匹配率（R=83.77%）下，调整 softmax 温度从 τ=28 到 τ=80 将 MacroScore 从 54.60 提升到 56.27，而硬顶-1 路由仅为 54.26。这表明**软 LoRA 混合本身就是一种正迁移机制**，任务特定性与专家复用之间需要校准。

6. **模型融合偏向**：FLEX 上最优 DISCO 模态融合为平衡的 0.5:0.5（图像:文本），而非原 FCIT 设置上的纯文本路由，证实弱化指纹后任务识别确实需要多模态证据。

7. **效率代价可控**：路由器额外内存最多 52.77 MiB（占检查点的 4.98%），推理端到端延迟变化在 -2.45%~+0.97% 之间，迁移代价较低。

## 七、优点

1. **问题识别精准且诊断扎实**：通过大量可视化（图 1、图 2）和受控指纹注入实验，将路由饱和问题分解为文本指纹和短序列两个独立因素，论证清晰。
2. **理论视角新颖**：将渐进式 LoRA 路由形式化为"软任务即类别的 MCIL"，搭建了两个领域（MCIT 与 CIL）之间的桥梁，为后续研究提供原则性接口，而不仅仅是技巧套用。
3. **基准设计合理**：FLEX 不是简单堆任务，而是通过共享格式组、弱化外部模板、配对可混淆数据集、扩大专家池等手段系统性地去除快捷路径，同时保留各数据集的native评估指标。
4. **受控实验典范**：PureLoRA 的精简设计、路由器替换协议（固定专家+固定生成）、Oracle 差距分析、种子/顺序/投影稳健性测试使结果具有高度可归因性。
5. **跨框架泛化验证**：在 4 种不同设计哲学的 MCIT 框架上验证，并进一步在 InternVL 骨干和 UCIT/TriGap 基准上检验迁移性，结论的普适性较强。
6. **诚实标注实现修正**：明确标出 "(fixed)" 配置并坦诚说明 HiDe 在初始移植中表现异常的原因（remain 融合的代数不等价与尺度问题），增强了实验可信度。

## 八、不足与局限

1. **FLEX 并非完全指纹无关**：作者自己也承认 FLEX"不是完全没有指纹"，仅弱化了显式界面到身份的捷径；更隐蔽的指纹（如数据集自身的统计规律、文本长度分布、视觉特征分布）可能仍然存在。CLIP 特征 t-SNE 可视化显示图像空间的 silhouette 值（0.125）高于文本空间（-0.012），说明视觉特征本身仍携带一定的任务可分性。

2. **骨干覆盖有限**：仅验证了 LLaVA-v1.5-7B 和 InternVL 两种骨干，且均基于 LoRA 微调范式。对更大模型（如 13B/34B 级）、其他专家形式（如 MoE 层内共享专家）、或动态扩展专家池的适应性尚未测试。

3. **CIL 路由器选择的代表性有限**：四种路由器都属于"冻结特征+轻量分类器"家族；更具表达力的深度增量学习方法（如基于梯度回传的增量分类器、基于回放的生成模型）未被探索。DDAS 需要每任务训练一个自编码器，其离线式训练与在线推断之间存在延迟。

4. **HiDe-LLaVA 的修复方案可能偏离原作者意图**：delta_mean 融合是对官方实现（ab_sum）的代数修正，虽有符号依据，但"何为正确的 remain 融合"本身存在争议。这意味着在 HiDe 上的结论可能仅适用于被修正的变体，而非原版方法。

5. **Oracle 差距的恢复上限有限**：即使采用最好的 CIL 路由器，恢复率也仅 28.3%~50.2%，剩余 50%+ 的任务识别错误未获解决。论文未提供错误模式的细粒度诊断（哪些类别混淆仍不可解、哪些是视觉/文本模态各自的缺陷），也未讨论更强的任务识别模型（如可学习的深度度量学习）是否能突破该瓶颈。

6. **任务顺序不具有内在难度曲线**：FLEX 采用目录顺序而非按难度/领域分布设计的顺序，虽然随机顺序实验显示对 SAME 影响不大，但对其他框架的任务顺序敏感性未被充分
