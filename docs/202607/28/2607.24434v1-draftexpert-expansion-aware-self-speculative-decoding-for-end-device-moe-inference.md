## 摘要
大型混合专家（MoE）语言模型因每个token仅激活少量专家而适用于终端设备部署，但其路由专家权重常超出加速器内存。我们面向延迟敏感的单用户场景，其中路由专家按需从CPU内存加载到GPU或从闪存加载到移动NPU。在此设定下，自推测解码面临新瓶颈：扩大草稿专家集可提升准确率但触发额外专家加载，而廉价的小足迹草稿接受率低；此外，验证多token块会激活目标专家并集，不再接近单次目标步骤。我们提出DraftExpert，一种面向专家卸载MoE推理的扩展感知型自推测解码框架。DraftExpert通过从冻结的目标MoE中自蒸馏残差、logit/token及路由器一致性信号，为每层训练一个轻量级常驻加速器的草稿专家。推理时，它采用固定足迹的共享+top-1+草稿专家起草器，结合置信度-扩展截断和目标专家预取，而最终token仍由目标模型精确验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B模型上，跨CPU-GPU和Flash-NPU卸载场景，DraftExpert将解码吞吐量平均提升1.45倍，草稿接受率提高至84~87%，预取命中率达86~88%。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：大型 MoE 语言模型在终端设备部署时具有优势——每个 token 只激活少量专家，但路由专家权重常超过加速器内存（如 GPU 显存或移动 NPU 的 SRAM）。为在资源受限设备上运行此类模型，实践中常将路由专家卸载到 CPU 内存或 Flash 中，按需加载到加速器（CPU→GPU 或 Flash→NPU），而共享层、注意力等非路由模块常驻加速器。
- **核心问题**：在专家卸载场景下，经典自推测解码的三个条件均被打破：
  1. **起草必须廉价**：增大草稿专家集（如 top-3）虽提高准确率，但会触发额外专家加载，起草速度下降。
  2. **并行验证应接近单步开销**：多 token 验证块会激活越来越多的目标专家并集，成本随块长增长。
  3. **接受率需足够高**：固定小足迹起草器（如 top-1）接受率低，且路由器预测不准确，影响验证时的专家预取。
- **整体含义**：本文首次将端侧 MoE 自推测解码重新定义为**专家集扩展问题**，提出扩展感知的设计原则——优化每次专家加载所获得的接受 token 数，而非单纯优化目标前向次数。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 核心思想
- **固定足迹起草**：使用共享路径 + top-1 路由专家 + 一个轻量级常驻加速器的**草稿专家**（draft expert），避免加载更多路由专家。
- **自蒸馏训练**：从冻结的目标 MoE 中蒸馏残差信号、logit/token 分布以及路由器一致性，使草稿专家能够恢复被省略的路由专家贡献，从而提高接受率而不增加路由专家加载量。
- **扩展感知运行策略**：
  1. **置信度-扩展截断**：结合草稿 token 置信度和预测的边际专家扩展数量，当低置信度且扩展大时停止起草。
  2. **目标专家预取**：利用路由器一致的草稿状态预测验证阶段可能需要的专家，异步预取，与起草计算重叠。

### 关键技术细节
- **草稿专家结构**：每个 MoE 层增加一个可训练的前馈网络（或类似专家模块），输入为当前隐藏状态，输出用于补偿 top-1 路径之外缺失的专家残差。
- **损失函数**（公式 11）：
  - 残差损失 \( \mathcal{L}_{\text{res}} \)：草稿专家输出与真实残差之间的 L2 距离。
  - logit 蒸馏损失 \( \mathcal{L}_{\text{logit}} \)：软标签 KL 散度。
  - token 损失 \( \mathcal{L}_{\text{tok}} \)：目标 top-1 token 的交叉熵。
  - 路由器一致性损失 \( \mathcal{L}_{\text{router}} \)：目标与草稿路由分布的 KL 散度。
- **动态截断策略**（算法 1）：
  - 对每个草稿 token i，计算置信度 \( q_i \) 和边际专家扩展 \( \Delta_i \)。
  - 若 \( q_i < \tau \) 且 \( \Delta_i > B_i \)（\( B_i \) 为预算），则截断。
- **预取**：根据草稿状态预测的专家 id，发起异步加载，仅等待未被预取且验证时需要的专家。

### 算法流程文字说明
1. 初始化 draft 块 D 为空，预测专家集 \(\hat{U}\) 为空，正在预取集合 P 为空。
2. 循环 i=1 到 K_max：
   - 使用共享+top-1+草稿专家路径生成候选 token v_i。
   - 计算置信度 q_i 和预测的验证专家集 \(\hat{E}_{l,i}\)。
   - 更新 \(\hat{U}\) 并计算边际扩展 \(\Delta_i\)。
   - 若低置信度且高扩展，则截断（不追加 v_i）。
   - 否则追加 v_i 至 D，并启动异步预取新增专家。
3. 等待必要的预取完成（若预取错过则按需加载）。
4. 使用完整冻结目标 MoE 并行验证 D 中所有 token，接受最长一致前缀，继续下一轮解码。

## 6. 主要结论与发现

- 专家卸载场景下，自推测解码的瓶颈从“目标前向次数”转变为“专家集扩展”。
- 固定足迹起草器（共享+top-1+草稿专家）结合自蒸馏可恢复高接受率（84~87%），同时保持起草成本接近 top-1。
- 路由器一致性蒸馏是关键：它使草稿状态能准确预测验证专家，从而支撑高命中率预取（86~88%）和有效截断。
- 综合使用控制验证扩展和预取后，端到端解码吞吐提升 1.45×（平均），而单纯增大 top-r 反而降低性能。
- DraftExpert 保持精确验证（最终 token 由目标 MoE 产生），不改变模型输出质量。
