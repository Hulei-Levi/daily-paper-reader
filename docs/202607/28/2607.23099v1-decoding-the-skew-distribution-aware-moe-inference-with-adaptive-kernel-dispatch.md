## 摘要
混合专家模型（MoE）推理由稀疏专家GEMM组成，其形状随运行时路由分布而变化。现有服务系统通常使用静态令牌计数桶选择融合MoE内核，忽略了决定瓦片填充、内存复用和内核效率的每个专家路由分布。我们引入了一个分布感知框架，用于建模和基准测试MoE推理。该框架将紧凑的Effective Experts指标与基于Dirichlet的逆向建模过程相结合，生成可控的路由分布，用于系统性硬件研究。利用该框架，我们展示了最佳融合MoE内核随路由偏斜和令牌数量而变化。我们进一步提出了DA-MoE，一个面向NVIDIA GPU的GPU驻留内核分发运行时，它能够将实时路由直方图与离线调优分布匹配，并在无需CPU-GPU同步的情况下选择接近最优的融合MoE内核。在HumanEval-X服务轨迹上，DA-MoE将DeepSeek-V3和Kimi K2的几何平均融合MoE延迟分别提升了1.16倍和1.29倍，峰值加速比达到1.40倍和1.56倍。

## Abstract
Mixture-of-Experts (MoE) inference consists of sparse expert GEMMs whose shapes vary with the runtime routing distribution. Existing serving systems typically select fused-MoE kernels using static token-count buckets, ignoring the per-expert routing distribution that determines tile padding, memory reuse, and kernel efficiency. We introduce a distribution-aware framework for modeling and benchmarking MoE inference. The framework combines the compact Effective Experts metric with a Dirichlet-based reverse-modeling procedure that generates controllable routing distributions for systematic hardware studies. Using it, we show that the best fused-MoE kernel changes with routing skew and token count. We further present DA-MoE, a GPU-resident kernel-dispatch runtime for NVIDIA GPUs that matches the live routing histogram to offline-tuned distributions and selects a near-optimal fused-MoE kernel without CPU--GPU synchronization. On HumanEval-X serving traces, DA-MoE improves geomean fused-MoE latency by 1.16X on DeepSeek-V3 and 1.29X on Kimi K2, with peak speedups of 1.40X and 1.56X.

### 1. 核心问题与整体含义（研究动机和背景）
- **背景**：大型语言模型（LLM）中的混合专家（MoE）架构通过稀疏激活子网络来平衡模型容量与推理成本，但推理时每个专家执行的通用矩阵乘法（GEMM）的形状随运行时路由分布动态变化——不同专家获得的令牌数不均衡且逐层、逐输入变化。
- **问题**：现有服务系统（如TensorRT-LLM、FlashInfer、vLLM）通常使用静态令牌数桶（token-count buckets）来选择预编译的融合MoE内核，完全忽略了每专家的路由分布特征（即每个专家实际处理的令牌数分布）。这导致：
  - 选择固定大小的MMA（矩阵乘累加）瓦片（tile）时，要么因瓦片过大而产生大量零填充浪费，要么因瓦片过小而增加权重矩阵的重载次数。
  - 无法适应同一令牌数桶内因路由偏斜不同而带来的最优内核变化。
- **整体含义**：本文首次系统揭示了MoE推理中的路由分布偏斜对内核选择的重要影响，并提出分布感知的自适应内核调度框架，以在不引入CPU-GPU同步开销的前提下实现近优内核选择，从而显著提升MoE推理延迟。

### 2. 方法论：核心思想、关键技术细节
- **核心思想**：将MoE推理的内核选择从依赖静态令牌数扩展到依赖实时的路由分布。通过离线调优建立分布到内核ID的映射，并在GPU上实时匹配分布并选择内核，所有操作均在CUDA Graph内完成，避免CPU-GPU同步。
- **关键技术细节**：
  - **Effective Experts（ef f_exp）指标**：定义为 `ef f_exp = (Σ_i t_i)² / Σ_i t_i²`，其中 `t_i` 为第 `i` 个专家的令牌数。该指标直观表示实际“有效”的专家数量，范围从1（完全集中）到N（均匀）。相比方差或熵，它具有跨批次规模不变性和直观的物理含义。
  - **Dirichlet反向建模**：使用对称Dirichlet分布 `Dir(α)` 生成可控路由分布。通过二分搜索调整集中参数 α，使生成分布的 `ef f_exp` 逼近目标值 `N/X`（X为偏斜倍数）。算法1详细描述了二分搜索过程。
  - **离线自动调优**：对每个令牌数桶（32,64,...,512），用不同α值（对应不同偏斜程度）生成多个合成路由分布；将每个分布的每专家令牌计数向量按降序排序并L2归一化，得到“示例”（exemplar）；对每个示例在所有TRTLLM融合MoE内核上进行基准测试，记录最佳内核ID，构建“示例→内核ID”查找表。
  - **在线调度（DA-MoE运行时）**：推理时，当路由器执行完毕后，在GPU上构建每专家直方图，排序并L2归一化，然后与当前令牌数桶的示例表进行余弦相似度匹配，选择相似度最高的示例对应的内核ID。
  - **条件CUDA Graph（CUDA 12.8+）**：利用 `cudaGraphConditional` 节点在CUDA Graph内部实现数据依赖的分支——在线匹配结果驱动SWITCH节点直接启动选定的融合MoE内核，无需CPU介入。这种设计将直方图构建、匹配、分支选择、内核启动全部保持在GPU上，开销约14μs。
- **算法流程**：见论文Algorithm 1（Dirichlet α的二分搜索）及图9（整体调度流）。

### 6. 主要结论与发现
- **MoE层推理性能不仅取决于令牌数桶，还严重依赖于每个桶内的路由分布**。最优内核随路由偏斜和令牌数变化而变化，静态分桶策略远非最优。
- **DA-MoE在真实服务负载上显著降低延迟**：
  - DeepSeek-V3：融合MoE延迟几何平均提升1.16×，峰值1.40×；端到端提升1.15×，峰值1.37×。
  - Kimi K2：融合MoE延迟几何平均提升1.29×，峰值1.56×；端到端提升1.26×，峰值1.51×。
  - 在大部分令牌数桶上，DA-MoE接近Oracle（偏差<4%），而NoDA偏差可达40-59%。
- **条件CUDA Graph的GPU驻留调度开销约14μs**，相对于MoE层延迟很小，几乎不侵蚀内核选择收益。
- **路由偏斜越大（如通过保留相同提示重复）DA-MoE加速比越大**（从1.21×到1.66×），说明方法在偏斜严重的场景尤其有效。
- **专家并行度提升时，DA-MoE收益先增后减**：EP=1时无收益（整体混合分布使静态选择已经稳健），EP=2-8时均有明显提升。
- **Dirichlet分布比Beta和指数分布能更准确地拟合真实路由分布**（余弦相似度0.97 vs 0.92/0.94）。

### 8. 不足与局限
- **实验覆盖局限**：
  - 仅在NVIDIA B200 GPU上测试，缺少对AMD、Intel或其他架构的验证。条件CUDA Graph是CUDA 12.8+专有特性，在HIP等环境中不可用，限制了可移植性。

- **开销的边界**：DA-MoE在线调度增加约14μs开销，对于小MoE模型（如Qwen3系列）可能无法被内核选择收益抵消，论文也承认这一点，但未做定量验证。
- **离线调优成本**：自动调优需要为每个令牌数桶遍历所有内核配置，对大规模部署可能耗时，且依赖TRTLLM闭源内核库的可用性。

- **应用限制**：DA-MoE需要CUDA 12.8+及条件CUDA Graph硬件支持，部署在老版本GPU或非NVIDIA平台不可行。
